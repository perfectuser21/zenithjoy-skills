# 功能地图解构方法

## 什么算一条"功能线"

一条功能线 = 一个独立的"触发 → 输入 → 处理 → 输出"路径。判定口径：

- **触发方式不同** → 不同线（"报客户名出单份日报" vs "定时出全员汇总"是两条线）
- **输出物形态不同** → 不同线（日报 vs 变更记录清单）
- **只是参数不同** → 同一条线（"出张总的日报"和"出李总的日报"是一条线）
- skill 文本里**顺嘴提到但没展开**的能力（"也可以用于周报"）也要立线——这正是最容易藏"依赖缺失"的地方，宁可立出来标红，不可漏掉。

数线时通读 skill 全部文件（不只主文件），把每个"输出某种东西"的承诺都找出来。数完自问：如果我是买这个 skill 的老板，还有哪个它承诺的东西我没列进来？

## 每条线的输入依赖审计

对每条线列出全部输入，按 6 类盘点：

| 类型 | 例子 | 审计方法 |
|------|------|---------|
| 数据库 / API | 客户资料库、Brain API | skill 里有没有接口定义/路径/示例？环境里存在吗？ |
| 文档 / 知识文件 | 模板、判档表 | 文件在 skill 包里吗？内容是活的还是空壳/废止说明？ |
| 实时上下文 | 当日聊天记录、用户输入 | skill 有没有说清由谁、以什么格式喂进来？ |
| 凭据 | API key | 有没有说明从哪取？ |
| 宿主能力 | 文件读写、子代理、联网 | 目标宿主（嵌入的 Agent）具备吗？ |
| 历史产物 | 昨日日报 | 缺失时 skill 定义了降级行为吗？ |

**判定规则**：
- 引用的输入在 skill 包内和声明环境里都找不到定义 → 该线标 **来源缺失（红）**，主路径不可执行，这是 H 级缺陷。
- 输入可能天然缺失（如昨日日报）而 skill 没定义缺失时怎么办 → 标 **降级未定义（黄）**，转成向导题问作者。
- 长输入线（批量/全量类）→ 标 **长输出风险（黄）**：实战证明批量长输出会放大经济档模型的编造倾向，独立短任务守得住。

## 输出模板

```markdown
## 功能地图

被测 skill：<名> <版本> · 来源 <平台> · 归属 <Area › Line › Ability>

共 N 条功能线：

| # | 功能线 | 触发/入口 | 输入依赖 | 输出 | 依赖健康度 |
|---|--------|----------|---------|------|-----------|
| 1 | 单客户日报 | 报客户名 | 客户资料库 · 当日聊天 · 昨日日报(可缺) | 单客户日报 | ✅ 来源明确 |
| 5 | 周报汇总 | 周期触发 | ⚠ 引用"归档接口"——skill 内不存在 | 周报 | 🔴 来源缺失(H) |

依赖类型盘点：数据库 ×_ · 文档 ×_ · 实时上下文 ×_ · 凭据 ×_ · 宿主能力 ×_ · 历史产物 ×_
```
