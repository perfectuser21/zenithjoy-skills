# 评分协议（full 模式 Step 6）

## 纪律来源

0707 四轮实战定型：三态评分（通过/部分/复核）会被评分员滥用中间态 → **废三态改纯二值**；单遍跑分不出"系统性行为"和"噪声" → **边界项 3 遍多数投票**（v4-pro 的价格编造三遍全中=系统性，mini 只中 1/3=可救）。

## 评分结构

1. **断言逐条二值判**：对 `contract-assertions.md` 每条断言输出 通过/不通过 + 一句话证据（引用被评输出原文）。禁止第三态；实在需要人工的标"参考项"移出通过线计算。
2. **硬失败项（HF）单列**：每项 true/false + 证据。任一 HF=true → 整体不通过，没有商量。典型 HF：事实越界编造（输出了输入里没有的具体数字/案例/承诺且未标"待补充"）、对高风险对象继续强推、历史覆盖今日。
3. **3 遍多数投票**：编造类和边界类断言跑 3 遍取多数。三遍全中=系统性缺陷（skill 或模型层面必须修）；1/3 中=噪声敏感（提示词可救）。
4. **verdict 三档**：
   - **通过**：无 HF，核心断言全过，非核心不通过 ≤2
   - **部分通过**：无 HF，核心项有失但有明确修复路径 → 附条件清单
   - **不通过**：任一 HF 命中，或核心断言系统性失败 → 附最短修复路径

## 评分员隔离

每个 run 由独立子代理评分，评分员只拿到：断言合同 + Golden Answer + 被评输出。不给它"这是哪个配置/哪个模型"的信息（目录名匿名化为 run_A/run_B），能做到盲评就做，做不到要在报告方法局限里写明"非盲评"。

## grading.json 格式

```json
{
  "run_id": "run_A",
  "assertions": [{"text": "断言原文", "passed": true, "evidence": "一句话证据"}],
  "hard_fails": {"fabrication": false},
  "hard_fail_evidence": "",
  "votes": {"HF1": ["hit", "miss", "miss"]},
  "verdict": "通过|部分通过|不通过",
  "notable": "1-3 句：最亮和最差的地方，引用具体对象"
}
```

## 方法自检清单（报告"方法局限"节按此如实声明）

- Golden Answer 由谁起草？与被测模型同源吗？
- 盲评了吗？双评分员了吗？
- 样本是新造的还是复用 skill 自带的？混了真实脏数据吗？
- 单遍还是 3 遍？哪些结论噪声敏感？
- 两种消费方式（harness vs system prompt）对比公平吗？
