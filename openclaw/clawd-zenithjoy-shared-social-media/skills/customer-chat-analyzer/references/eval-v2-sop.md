# Eval V2.0 SOP：客观评测与 Baseline 对比流程

本文件用于更新 customer-chat-analyzer 的评测流程。V2.0 的目标是让 Eval 更全面、公正、客观、可复测。

## 一、适用场景

使用本 SOP 当用户要求：

1. 测试或演示 customer-chat-analyzer 的效果。
2. 对 Skill 进行严格验收。
3. 与无 Skill 输出做 baseline 对比。
4. 修改 Skill 后做回归测试。
5. 评估 Skill 是否可交给团队长期使用。

## 二、Eval 组成

每次正式 Eval 至少包含 5 个文件或记录：

1. `eval_input.md`：测试输入。
2. `golden_answer.md`：标准答案。
3. `baseline0_output.md`：普通无模板输出。
4. `baseline1_output.md`：普通模板输出。
5. `skillrun_output.md`：使用 customer-chat-analyzer 后的输出。
6. `eval_report.md`：评分、对比、结论。

如果当前环境无法启动独立模型实例生成 Baseline 0 和 Baseline 1，必须在报告中明确说明“本次仅完成 Skill Run 回归评分，baseline 待团队在独立会话中补跑”，不得假装已经完成盲评 baseline。

## 三、测试集设计

### 1. 样本规模

| 场景 | 最低样本数 | 推荐样本数 |
| --- | ---: | ---: |
| 快速冒烟测试 | 6 | 6 |
| 小型回归测试 | 12 | 15 |
| 正式上线验收 | 30 | 30-50 |
| 重大规则更新 | 50 | 50+ |

### 2. 正式测试必须覆盖的样本类型

1. A1 初聊客户。
2. A1 防御客户。
3. A1 模糊询价客户。
4. A1 调研型询价客户。
5. A2 已完成入口动作客户。
6. A2 使用中但犹豫客户。
7. A3 中阶产品客户。
8. A3 结果和回本顾虑客户。
9. A4 已签约付款客户。
10. A4 启动边界客户。
11. 多人决策客户。
12. 同行比较客户。
13. 拖延客户。
14. 高风险保结果客户。
15. 拒绝配合客户。
16. 历史状态冲突客户。

## 四、Baseline 设计

### Baseline 0：普通分析

提示词：

```text
请分析以下客户聊天记录，判断客户意向、主要顾虑，并给出下一步跟进建议。
```

### Baseline 1：普通模板分析

提示词：

```text
请按以下结构分析客户聊天记录：
1. 客户阶段
2. 客户意向
3. 主要顾虑
4. 下一步动作
5. 建议回复
```

### Skill Run：正式 Skill 输出

提示词：

```text
@customer-chat-analyzer
请按 Skill 标准，对以下客户聊天记录生成客户当日日报。
如果有多个客户，请先输出每个客户的单客户当日日报，再输出所有客户当日总结日报。
```

### 公平对照原则

1. 三组使用完全相同的客户聊天记录。
2. 三组使用完全相同的产品背景和历史材料。
3. 三组不得在测试过程中额外补充不同提示。
4. 评分时尽量盲评，只标记“输出 A/B/C”。
5. 评分后再揭示哪一份是 Skill Run。
6. 不因输出更长加分，只因判断更准、证据更充分、动作更可执行加分。

## 五、Golden Answer 流程

1. 运行任何输出之前，先按 `eval-v2-golden-answer-template.md` 写好标准答案。
2. Golden Answer 必须写每个客户的正确阶段、推进信号、询价类型、主缺口、风险等级、下一步方向和禁止动作。
3. 如果某项证据不足，标准答案必须写“证据不足”，不得强行定论。
4. 评分时允许不同表述，但核心判断不得偏离 Golden Answer。

## 六、评分流程

1. 阅读 `eval-v2-scorecard.md`。
2. 对 Baseline 0、Baseline 1、Skill Run 分别打分。
3. 检查硬性失败项。
4. 计算总分。
5. 比较 Skill Run 与 Baseline 的提升。
6. 输出 Eval 报告。

## 七、通过标准

### 普通通过

1. Skill Run 总分不低于 85 分。
2. 无硬性失败项。
3. 阶段判断不低于 11/14。
4. 高风险识别不低于 8/10。
5. 下一步动作不低于 9/12。
6. 两层日报结构不低于 6/8。

### 优秀通过

1. Skill Run 总分不低于 92 分。
2. 无硬性失败项。
3. Skill Run 比 Baseline 1 至少高 8 分。
4. 高风险识别、询价分级、阶段判断均无严重错误。
5. 多客户汇总可直接用于团队复盘。

### 不通过

任意满足：

1. Skill Run 总分低于 85 分。
2. 出现任一硬性失败项。
3. 高风险识别低于 6/10。
4. 阶段判断低于 9/14。
5. 下一步动作大量空泛。
6. Skill Run 不明显优于 Baseline 1。

## 九、输出 Eval 结果时的注意事项

1. 如果只是快速演示，可以使用现有 6 客户样例，但必须说明这只是冒烟测试，不代表正式上线验收。
2. 如果用户要求“公正、客观、全面”，必须使用 100 分评分卡和 Golden Answer。
3. 如果没有跑 baseline，不能写 Skill 比 baseline 高多少分。
4. 如果没有独立评分者，不能写“盲评通过”。
5. 如果出现硬性失败项，必须明确写“不通过”，不能用总分掩盖。
