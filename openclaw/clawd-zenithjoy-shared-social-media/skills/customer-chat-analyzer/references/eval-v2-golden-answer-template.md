# Eval V2.0 Golden Answer 标准答案模板

本文件用于在评分前固定每个测试样本的标准答案，避免评分者根据模型输出临时改变评判口径。Golden Answer 不要求逐字匹配，但核心判断必须作为评分依据。

## 一、Golden Answer 使用规则

1. 每个测试样本必须先写 Golden Answer，再运行 Baseline 和 Skill Run。
2. Golden Answer 只写关键判断，不写完整日报。
3. 评分时允许不同表达，但不允许核心判断偏离。
4. 标准答案必须引用客户原话或聊天事实。
5. 阶段判断必须按客户已完成动作，不按热情程度。
6. 问价必须区分购买型、调研型、模糊询价。
7. 高风险客户必须写明禁止动作。
8. 如果证据不足，Golden Answer 必须写“证据不足”，不得强行设定唯一结论。

## 三、多客户 Golden Answer 汇总模板

```text
测试样本编号：
客户总数：
是否有历史材料：是 / 否
是否要求文件输出：是 / 否

| 客户 | 正确阶段 | 推进信号 | 询价类型 | 主缺口/风险 | 下一步方向 | 禁止动作 |
| --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  |

汇总日报标准要求：
1. 必须先输出所有单客户日报。
2. 每个客户必须包含当日突出点。
3. 所有客户总结日报必须基于单客户日报。
4. 汇总日报默认只保留：今日总览、当日突出点、明日重点任务、团队话术/物料提醒。
5. 明日重点任务必须按任务主题聚合，不逐客户重复。
```

## 四、示例 Golden Answer

```text
样本编号：eval_case_005_research_price
客户名称：钱总
样本类型：询价分级 / 调研型询价

1. 正确阶段：A1
阶段依据：
- 客户只是做市场调研，未购买、未预约、未提交资料、未确认启动。
- 客户原话：“今年不一定做，只是老板让我做市场调研，收集几家供应商价格做预算。”
- 不可升级阶段的原因：问价不等于购买，客户明确排除近期启动。

2. 推进信号：弱
推进信号依据：
- 有问价行为：“系统项目大概多少钱”。
- 但客户明确“不用约会，也不用催我付款”。
- 是否应该收口：否。

3. 询价类型：调研型询价
判断依据：
- 问价用于预算和供应商收集，不是购买决策。

4. 主缺口：确认感，其次安全感
判断依据：
- 客户需要价格区间、适用条件和判断标准。
- 客户不希望被催付款，需要低压力沟通。

5. 风险等级：正常偏低意向
风险依据：
- 没有要求保证结果，也没有拒绝边界；只是启动意图不足。

6. 当日突出点方向：卡点 / 动作
标准突出点：
- 客户明确只做预算调研，不应强推付款或会议。

7. 下一步动作方向：轻触达
合格动作必须包含：
- 对象：销售。
- 动作：发送价格区间、适用条件、不同方案判断标准。
- 时间或条件：今日内发送，3-5 天后轻触达。
- 资料、交付或边界：说明该区间仅供预算参考，正式方案需诊断后确认。

8. 建议回复必须做到：
- 承认客户只是做预算。
- 给价格区间和适用条件。
- 不催付款，不强行约会。

9. 禁止动作：
- 不得判断为强购买意向。
- 不得催付款。
- 不得直接推合同。

10. 可接受变体：
- 可写为 A1 低意向 / A1 调研客户。
- 推进信号可写“弱推进”或“弱询价信号”。
```
