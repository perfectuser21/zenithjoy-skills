# 飞书 CRM 驱动的朋友圈内容规划与文案生成

## 目标与边界

把朋友圈作为“客户结构驱动的动态内容系统”：销售 CRM、企业资料、内容运营和发布执行分别位于部门隔离的飞书 Base。跨部门只传递脱敏快照、稳定 ID 和已批准的冻结内容，不传递客户姓名、联系方式或完整聊天。

飞书是数据、展示、审核和状态管理中枢；OpenClaw 是生成与编排层；安卓微信是发布执行端。发布只能在用户明确授权、飞书任务已批准且微信专用发布器通过预检后进行。本 Skill 不直接修改 CRM 客户阶段，也不得把抖音控制器当作微信发布器。

## 必须读取的参考

- 连接、校验或写回飞书 Base 时，读取 [飞书 Base 数据契约](references/feishu-base-contract.md)。
- 生成当天朋友圈正文时，读取 [朋友圈内容系统](references/content-system.md)。
- 创建或执行发布任务时，读取 [OpenClaw 安卓微信发布契约](references/openclaw-wechat-publishing.md)。
- 在悦升云端运行时读取 [悦升云端部署绑定](references/yueshengyun-deployment.md)。
- 需要精确整数分配时，运行 `scripts/allocate_schedule.py`。

## 数据源要求

两个 ZIP/Skill 文件是处理规则，不是每天的业务数据输入。悦升云端运行时数据来自四个独立飞书 Base：

1. **企业资料中心**：企业档案、产品服务和目标客户画像，只提供已批准企业事实。
2. **销售 CRM**：客户、A1-A4 阶段、沟通分析和跟进状态，不与抖音线索表混用。
3. **内容运营中心**：只接收 CRM 的聚合/脱敏洞察，保存策略、朋友圈文案和审核状态。
4. **发布执行中心**：只接收已批准的冻结正文和附件，保存设备路由、发布状态、证明和效果。

初始化优先从 OpenClaw 的租户注册信息定位四个 Base，再从内容规划配置和发布系统配置取得跨域绑定。用户也可以直接提供任一 Base 链接或租户标识。Skill 必须自行读取表、字段 schema 和必要记录；Base 中已经存在的信息不得再次要求用户手工填写。

如果工作台没有 CRM 绑定、企业资料或发布配置，输出缺口及拟建结构。只有用户明确要求创建或补齐后，才修改飞书表结构。

初始化完成后的日常运行，用户通常只需要提供运行意图，例如“生成本周排期”或“生成今天的朋友圈”。日期、时区、发布量、品牌/账号和写回策略优先从 Base 的有效配置记录读取；只有 Base 中没有对应配置、存在多个候选或用户明确要求单次覆盖时，才向用户补问。

用户在对话中明确提供的值可作为本次运行的临时覆盖，但必须标注“本次临时覆盖”，不得默默写回 Base，也不得把聊天中的旧值长期替代 Base 正式配置。

### 运行所需的最小信息

周规划至少需要：

1. 已解析的租户、企业资料 Base、销售 CRM Base、内容运营 Base 与发布执行 Base 绑定。
2. CRM 表中的有效客户及当前 A1-A4 阶段。
3. 一条有效的企业资料记录。
4. 至少一条当前主推产品或服务记录。
5. 内容策略配置中的本周发布总量 `weeklyTotal`，或用户本次明确覆盖的数值。
6. 配置表中的周起止口径和时区。

每日生成至少需要：

1. 销售 CRM 生成的已脱敏客户洞察，以及企业资料中心和内容运营中心中的有效配置。
2. 目标日期。
3. 当天发布量；优先读取已保存周排期中的 `dailyTotal`，其次读取策略配置，最后才向用户询问。
4. 当天 CRM 快照。
5. 可用产品与素材事实、品牌语气、禁用表达。

缺少 CRM 绑定、CRM 阶段、企业资料或主推产品时，不生成看似完整的正式文案；输出“缺失信息清单”和最小补充动作。

## 统一客户阶段

为避免与客户聊天分析 Skill 冲突，默认使用同一套从早期到成交落地的定义：

- A1：刚了解、初聊或收集信息，尚未完成低风险入口动作。
- A2：已预约演示、提交资料、完成诊断或购买低价引流品，正在验证小结果。
- A3：已购买中阶产品或单板块方案，正在评估正价项目、合同和付款。
- A4：已签署正价产品合同并完成付款，进入实施、运营、续费或转介绍阶段。

如果 Base 已有其他阶段定义，先读取并展示映射；未经用户确认，不把同名但含义不同的 A1-A4 混用。

## 使用模式

### 初始化与绑定

通常只需要用户给租户名称或任一工作台 Base 链接。先读取 OpenClaw 租户注册、内容规划配置和发布系统配置，再定位四个业务域，完成：

- 表名和字段映射。
- A1-A4 选项及含义校验。
- 选择目标日期有效的企业资料版本、主推产品和内容策略。
- 企业资料、产品素材、CRM 快照、排期和效果表完整性检查。
- 输出后续运行可直接复用的绑定摘要，包括租户、Base、各 `table_id` 和字段映射；不得输出认证凭据、Cookie、设备解锁信息或账号密码。
- 核验内容工作台、微信账号、安卓 phone profile、OpenClaw Node 和微信发布器的租户绑定，但初始化检查不得打开微信或执行发布。
- 数据缺口清单。

Base 中已经存在的信息直接读取，不重复向用户提问。只有以下情况才请求用户确认：多个品牌或有效版本无法唯一选择、A1-A4 含义冲突、字段无法可靠映射、权限不足，或必需记录确实缺失。

只检查时不创建或修改字段。用户明确要求“按标准补齐/创建”后，才写入 Base schema；缺失信息应优先建议补到 Base，而不是长期保存在对话里。

### 周规划

读取周初 CRM 快照、企业资料、主推产品和发布约束，生成周一至周日排期。周规划只做排期，不生成完整朋友圈正文。

### 每日生成

读取当天 CRM 快照并与周初快照对比，判断是否校准当天内容分布，再根据已批准事实生成可直接发布的文案。

### 剩余排期修正

如果客户结构连续两天达到校准阈值，先给出剩余排期调整建议。只有用户明确要求重排或保存时，才覆盖未来日期的排期；已发布记录不得覆盖。

### 复盘

读取排期、实际发布和效果记录，分析各客户阶段、内容支柱、主题和互动动作的表现，输出下周调整建议。没有效果数据时，只能做内容结构检查，不得声称转化有效。

## 标准执行逻辑

### 1. 解析飞书 Base

按 `$lark-base` 的规则解析 Base URL，定位所需表。读取字段 schema 后再读取记录，不凭表名或字段名猜测含义。

若存在多个候选表，按字段契约匹配；仍无法唯一确定时，列出候选及缺失字段，请用户选择。

### 2. 读取并验证企业信息

生成任何具体主题或正文前，至少确认：

- 企业名称、品牌或个人 IP 名称。
- 企业定位和核心业务。
- 目标客户及典型场景。
- 当前主推产品、核心价值、适用边界和交付内容。
- 品牌语气。
- 禁用表达、合规边界和不能承诺的结果。

案例、客户原话、价格、数据和效果必须有来源记录。缺少来源时不用案例型表达，改用方法、FAQ、认知教育或边界说明。

### 3. 生成 CRM 快照

只统计同时满足以下条件的客户：

- 阶段字段是有效的 A1、A2、A3 或 A4。
- 客户记录未标记为无效、重复或删除。
- “纳入内容规划”不为否；没有该字段时按数据契约记录口径风险。
- 快照时间符合本次周初或当天口径。

保存或报告快照时间、有效客户总数、各阶段人数和占比。CRM 数据只读，不因内容规划结果反向改写客户阶段。

### 4. 计算周内容结构

```text
totalCustomers = A1_count + A2_count + A3_count + A4_count
stage_ratio = stage_count / totalCustomers
stage_content_count = weeklyTotal × stage_ratio
```

整数分配采用最大余数法。若 Base 的“内容策略配置”表提供了阶段优先权重，按 `阶段得分 = 客户占比 × 阶段权重` 计算，再把四个阶段得分归一化为内容占比；没有权重时使用原始客户占比。

### 5. 分配每天发布量

用户未指定每日发布量时：

1. 周一至周五尽量均衡。
2. 周末不低于工作日，条件允许时高 1-2 条。
3. 每日合计必须等于 `weeklyTotal`。
4. 每日阶段分布的行合计必须等于当天 `dailyTotal`，整周各阶段列合计必须等于周阶段内容量。

### 6. 每日校准

默认偏差阈值 `deviationThreshold = 10%`，可从 Base 配置读取。

```text
stage_deviation = abs(today_stage_ratio - week_stage_ratio)
```

- 所有阶段偏差均小于阈值：沿用当天周排期。
- 任一阶段偏差大于或等于阈值：按当天 CRM 占比重算当天阶段内容分布。
- 周初基线优先读取已保存的“CRM 快照”；没有跨会话基线时，要求用户提供原周计划或先重新建立周基线。
- 日校准不自动增加 `dailyTotal`。
- 连续两天触发校准：建议重做本周剩余排期，但不自动覆盖。

### 7. 阶段到内容策略

| 阶段 | 内容任务 | 优先内容支柱 |
|---|---|---|
| A1 | 建立确认感、安全感和基础信任，推动低风险入口动作 | 认知教育、痛点共鸣、方法干货、FAQ |
| A2 | 展示小结果和使用路径，推动中阶产品 | 方法干货、小结果案例、FAQ、场景解释 |
| A3 | 解释持续价值、投入产出、交付边界和决策风险 | 案例结果、对比决策、风险边界、转化成交 |
| A4 | 支持实施、采用、复盘、续费和转介绍 | 交付过程、运营方法、成果复盘、客户共创 |

确定每条内容的客户阶段、内容支柱、表达角度、意图和主题后，再读取对应企业资料和素材。

### 8. 生成和校验文案

每条文案必须：

- 服务一个主要客户阶段和一个内容任务。
- 使用可追溯的企业、产品或素材事实。
- 只提供一个核心观点和一个互动入口。
- 不编造案例、数据、客户原话、价格或效果。
- 不出现“模板、流程、公式、变量、模块、A1-A4、P1-P6”等内部生产痕迹。

### 9. 文案建立、展示与写回

正式文案的权威记录必须位于内容工作台的“朋友圈内容”表；OpenClaw 对话中的文本只作为预览。建议在飞书应用模式或视图中提供“今日待审”“发布日历”“待发布”“发布失败”“已发布”页面。

只有用户明确要求生成并保存，或工作台配置了已获授权的自动生成计划时：

- 周规划写入“朋友圈内容/排期”表。
- 周规划和日校准同步写入“CRM 快照”表，或把等价快照字段写入排期批次。
- 当天文案写入对应日期的内容记录；优先按租户 + 日期 + 账号 + 序号幂等更新，避免重复创建。
- 复盘写入“发布效果”或指定复盘字段。
- 不覆盖已发布正文；需要改已发布记录时必须再次明确目标。

### 10. 发布任务管理

状态固定按以下方向流转：

```text
草稿 -> 待审核 -> 已批准 -> 待发布 -> 发布中 -> 已发布
                                      \-> 发布失败
草稿/待审核/已批准/待发布 -> 已取消
```

- 生成文案不等于批准发布；只有明确的审核动作可以进入“已批准”。
- 发布执行前必须再次确认租户、微信账号、phone profile、设备、排期时间、正文和附件。
- 只有微信专用 OpenClaw 安卓发布器可领取“已批准/待发布”任务；发布器不存在、节点离线、账号不匹配或出现登录/验证码/风控时停止。
- 发布器必须使用任务幂等键和设备锁，一次只处理一条；成功后写回实际发布时间、微信账号、设备、证明截图和回执。
- 没有可核验回执时不得标记“已发布”；失败要保留原因和可重试状态，不自动无限重试。

| 日期 | dailyTotal | 客户阶段分布 | 内容支柱 | 表达角度 | 意图 | 主题方向 | 资料来源 |


### 复盘

- 核心结论。
- 各阶段和内容支柱表现。
- 高效主题及证据。
- 低效主题及证据。
- 下周内容比例与主题调整。
- 数据缺口和口径提醒。

## 特殊情况

- 当天有必发活动、直播、新品或通知：先占用当天条数，剩余条数再按 CRM 结构分配。
- CRM 有效客户为 0：停止比例计算，提示修复 CRM 或由用户明确批准临时分布；不得自行猜测。
- 企业资料存在多个有效版本：优先使用生效日期覆盖目标日期的记录；无法确定时请用户选择。
- 产品或案例已过期：不用于文案。
- 任一 Base 无法访问：报告实际权限或认证问题，不退回猜测数据模式。
- 微信发布器未安装或手机节点离线：仍可生成和审核文案，但只能停在“待发布”，不得声称已自动发布。

## 禁止事项

1. 不用手填的猜测人数替代飞书 CRM 正式口径。
2. 不在周规划阶段生成完整正文。
3. 不修改 CRM 客户阶段或客户资料。
4. 不未经授权写回、覆盖或创建飞书记录。
5. 不虚构案例、数据、客户反馈、价格、成交结果或收益金额。
6. 不自动突破 `dailyTotal` 或 `weeklyTotal`。
7. 不把同名但含义相反的 A1-A4 阶段直接混用。
8. 不以“已发送给发布器”代替“已发布”；必须有微信端可核验回执。
9. 不调用抖音控制器、裸 ADB 或未登记设备发布微信朋友圈。
10. 不跨租户读取 CRM、企业资料、微信账号、手机或发布记录。
