# OpenClaw 安卓微信发布契约

本文件只在创建、校验或执行朋友圈发布任务时读取。内容规划和只读初始化不需要访问手机。

## 角色边界

- 飞书内容工作台：任务来源、人工审核、状态展示和发布回执的权威记录。
- `wechat-moments-planner`：生成排期、文案和发布任务，不伪造手机结果。
- OpenClaw 微信发布器：领取已批准任务，调用租户绑定的 Node 与微信专用控制器。
- 安卓微信：唯一实际发布端。

不得用 Douyin/抖音控制器代替微信发布器。若运行环境没有微信专用 Skill、控制器或已验证的账号绑定，返回“发布能力未就绪”，内容任务保持待发布。

## 发布任务最小字段

| 字段 | 要求 |
|---|---|
| 发布任务ID | 稳定主键，也是幂等键来源 |
| tenant_id | 必须与 CRM、工作台、设备和微信账号一致 |
| 内容记录ID | 指向已批准的朋友圈内容 |
| 微信账号标识 | 使用非敏感、可核验的账号 marker |
| phone_profile | 租户登记的手机 profile |
| node | 租户登记的 OpenClaw Node |
| 正文快照 | 审核时冻结，发布器不得擅自重写 |
| 附件快照 | 审核时冻结，并保留来源 |
| 计划发布时间 | 包含时区 |
| 审核状态/审核人/审核时间 | 三者齐全才允许发布 |
| 发布状态 | 待发布/发布中/已发布/发布失败/已取消 |
| attempt_count | 限制重试次数 |
| actual_published_at | 成功后填写 |
| proof | 成功页面截图或等价可核验证据 |
| failure_reason | 失败时必填 |

## 执行门槛

执行前全部满足：

1. 任务状态为“已批准”或“待发布”，正文和附件与审核快照一致。
2. 当前时间符合计划和租户时区；人工立即发布必须有当次明确授权。
3. Node 在线，phone profile、设备 serial/model 与租户登记一致。
4. 取得该设备的独占锁；同一手机不得并发操作。
5. 微信前台账号与任务账号 marker 一致。
6. 微信处于正常登录状态，没有验证码、实名、人脸、设备确认或风控挑战。

任一条件不满足就停止，不切换到其他租户设备或账号求成功。

## 发布与回执

1. 以发布任务ID构造幂等键；先检查该任务是否已有成功回执。
2. 发布器只使用租户登记的微信控制器操作朋友圈入口、正文和附件。
3. 点击最终发布前再次比对正文摘要、附件数量和目标账号。
4. 成功后取得可核验的朋友圈结果页证据，写回实际发布时间、账号、设备、证据和状态。
5. 无法确认成功时写“发布失败/结果不确定”，不得重试点击最终发布，也不得标记“已发布”。
6. 最终退出微信敏感页面并释放设备锁。

登录挑战、验证码、人脸、支付、安全确认和账号切换不得自动绕过。失败自动重试最多一次，并且只有在能证明第一次没有完成发布时才允许。
