# 飞书 Base 数据契约

本契约按部门和敏感度拆分四个飞书多维表格（Base）：企业资料中心、销售 CRM、内容运营中心、发布执行中心。不同 Base 通过稳定 ID 和显式配置绑定，不使用跨部门可识别个人的信息副本。

- **销售 CRM**：客户事实、沟通分析、A1-A4 阶段和跟进状态的唯一权威来源。
- **企业资料中心**：经过确认的企业事实、产品服务和目标客户画像。
- **内容运营中心**：聚合且脱敏的客户洞察、内容策略、朋友圈内容和审核状态。
- **发布执行中心**：已批准的冻结内容、账号/设备路由、发布证明和效果。

不同企业不得共用任何一个业务 Base、客户表、设备账号或发布队列。不同部门也不得靠隐藏视图实现隔离；访问边界必须由独立 Base 协作者或高级权限控制。

## 一、Base 定位

初始化优先从 OpenClaw 租户注册信息取得四个 Base URL，再从内容规划配置与发布系统配置取得跨域绑定。用户也可直接提供租户标识或任一工作台 URL。不得要求用户重复粘贴飞书中已有的企业、产品、CRM、品牌或策略信息。使用 `$lark-base`：

1. 解析四个业务域 Base，核验它们都绑定同一 `tenant_id` 和企业名称。
2. 读取内容规划配置与发布系统配置，确认企业资料、销售 CRM、内容运营和发布执行之间的绑定一致。
3. 分别列出各 Base 的 Table，定位候选表。
4. 先读取字段 schema，再建立字段映射。
5. 只投影本次所需字段读取记录，并检查分页完整性。

完成识别后输出绑定摘要，供后续运行复用；摘要可以包含 `base_token`、`table_id`、字段名和 `field_id`，但不得包含访问令牌、Cookie、密钥或其他认证凭据。

若同一类表有多个候选，先根据字段完整度、启用状态、生效日期和账号/品牌匹配自动消歧；仍无法唯一选择时才询问用户。

默认以用户身份读取。认证或权限问题按 `$lark-shared` 处理。不要把 BaseApp、普通电子表格 Sheets 和多维表格 Base 混为一类。

## 二、核心表

### 0. 跨域配置

内容运营中心只保存企业资料 Base、销售 CRM Base、时区、发布量和内容策略；发布执行中心保存内容运营 Base、非敏感账号 marker、OpenClaw Node、phone profile 和发布器状态。设备配置不得写入销售 CRM 或内容运营中心，也不得在任何 Base 中保存密码、Cookie、验证码或设备解锁信息。

### 1. 客户 CRM（独立 CRM 表必需）

一行代表一个客户。至少需要：

| 标准字段 | 必需 | 建议类型 | 用途 |
|---|---|---|---|
| 客户ID | 是 | 文本/自动编号 | 去重和稳定识别 |
| 客户名称 | 是 | 文本 | 展示与核验 |
| 当前阶段 | 是 | 单选 | A1/A2/A3/A4 统计 |
| 阶段更新时间 | 是 | 日期时间 | 确认快照口径和变化 |
| 客户状态 | 是 | 单选 | 排除无效、重复、已删除客户 |
| 纳入内容规划 | 推荐 | 复选框 | 明确是否进入朋友圈人群结构 |
| 负责人 | 推荐 | 人员 | 分团队或账号规划 |
| 行业/客户类型 | 推荐 | 单选/多选 | 细分主题和表达场景 |
| 核心需求 | 推荐 | 文本 | 痛点与选题来源 |
| 当前顾虑 | 推荐 | 文本/多选 | FAQ 和风险内容来源 |
| 最近沟通时间 | 推荐 | 日期时间 | 判断数据新鲜度 |
| 推进信号 | 推荐 | 单选/多选 | 确定转化内容强度 |
| 最近分析记录ID | 推荐 | 文本 | 关联聊天分析输出 |
| 原始沟通来源 | 推荐 | 文本/链接 | 追溯聊天或日报证据 |

允许阶段字段使用中文名，但必须唯一映射到统一 A1-A4。阶段为空或无法映射的客户不进入占比计算，并计入数据质量提醒。

### 2. 企业资料（企业资料中心必需）

建议一行代表一个品牌资料版本：

| 标准字段 | 必需 | 用途 |
|---|---|---|
| 资料版本ID | 是 | 稳定引用 |
| 企业/品牌名称 | 是 | 明确发言主体 |
| 生效日期 | 是 | 选择目标日期有效版本 |
| 是否启用 | 是 | 排除历史草稿 |
| 企业定位 | 是 | 确定认知表达 |
| 核心业务 | 是 | 限制主题范围 |
| 目标客户 | 是 | 明确内容对象 |
| 典型场景/痛点 | 是 | 选题和开场来源 |
| 差异化优势 | 推荐 | 建立可信区别 |
| 品牌语气 | 是 | 控制语言风格 |
| 禁用表达 | 是 | 防止违规或不符合品牌 |
| 合规与承诺边界 | 是 | 限制效果、价格和结果表述 |
| 账号/负责人 | 推荐 | 多品牌或多账号路由 |

### 3. 产品与素材库（企业资料中心与内容运营中心生成正文必需）

至少要有一条启用的主推产品或服务记录：

| 标准字段 | 必需 | 用途 |
|---|---|---|
| 素材ID | 是 | 稳定引用 |
| 素材类型 | 是 | 产品/FAQ/案例/客户原话/数据/活动/图片 |
| 标题 | 是 | 检索和展示 |
| 正文或事实摘要 | 是 | 文案事实来源 |
| 适用产品 | 推荐 | 产品路由 |
| 适用客户阶段 | 推荐 | A1-A4 内容路由 |
| 适用目标客户 | 推荐 | 人群匹配 |
| 来源/证据 | 案例和数据必需 | 可追溯事实 |
| 是否可公开 | 是 | 隐私与品牌边界 |
| 生效日期/失效日期 | 推荐 | 防止使用过期资料 |
| 是否启用 | 是 | 控制素材状态 |

产品记录还应包含：核心价值、适用条件、不适用条件、交付内容；价格、交付周期和效果数据只有在来源明确且允许公开时使用。

### 4. 内容策略配置（内容运营中心推荐）

可存放：

- 每周默认发布量。
- 各账号时区。
- 日校准阈值，默认 10%。
- 各阶段内容优先权重，默认均为 1。
- 工作日/周末发布偏好。
- 禁发日期和时段。
- 必发主题和活动窗口。
- 默认 CTA 与禁止 CTA。

### 5. CRM 快照（销售 CRM 生成，内容运营中心只接收脱敏版本）

一行代表一个确定口径下的客户结构快照，建议字段：

- 快照ID。
- 快照时间和时区。
- 快照类型：周初/每日/人工复核。
- 账号、品牌或负责人范围。
- A1、A2、A3、A4 人数。
- 有效客户总数、异常阶段记录数、排除记录数。
- CRM 源表、过滤条件和阶段定义版本。

周计划写回时同步保存周初快照，日校准时保存当天快照。没有快照表时，可把周初人数、口径和时间保存在排期批次记录中；若两者都没有，跨会话运行时不得凭记忆构造周初基线。

### 6. 朋友圈内容与排期（内容运营中心保存结果时必需）

建议字段：

| 字段 | 用途 |
|---|---|
| 排期ID | 稳定主键 |
| 日期 | 定位当天 |
| 序号 | 区分同日多条内容 |
| 账号/品牌 | 多账号路由 |
| 目标客户阶段 | A1-A4 |
| 内容支柱 | 认知/痛点/方法/案例/日常/转化 |
| 表达角度 | 场景、对象、时间轴、权衡等 |
| 内容意图 | 认知、信任、互动、咨询、成交等 |
| 主题方向 | 周计划主题 |
| 文案正文 | 当天成稿 |
| 素材附件 | 待发布图片/视频附件 |
| 素材来源ID | 追溯使用事实和附件来源 |
| 审核状态 | 草稿/待审核/已批准/已驳回 |
| 发布状态 | 未排期/待发布/发布中/已发布/发布失败/已取消 |
| 审核人/审核时间 | 证明发布已获批准 |
| CRM快照时间 | 记录计算口径 |
| 校准状态 | 原计划/日校准 |

按“tenant_id + 日期 + 微信账号 + 序号”幂等写入。默认不覆盖状态为“已发布”的正文和附件。

### 7. 发布任务与回执（发布执行中心自动发布必需）

每条发布任务只能关联一条已经批准的内容记录。至少包含：发布任务ID、tenant_id、内容记录ID、微信账号 marker、OpenClaw Node、phone profile、计划发布时间和时区、冻结正文、冻结附件、审核人、审核时间、发布状态、尝试次数、幂等键、实际发布时间、证明截图/证据、失败原因和下次允许重试时间。

生成文案与创建发布任务是两种动作。没有明确发布授权时可以生成和审核内容，但不得自动把记录推进到“发布中”。

### 8. 发布效果（发布执行中心复盘时必需）

建议字段：

- 排期ID或朋友圈记录ID。
- 实际发布时间。
- 点赞数、评论数、私信人数。
- 新增咨询数、新增好友数、有效线索数。
- 成交数和成交金额；只有口径明确时统计。
- 客户反馈或典型问题。
- 数据统计截止时间。
- 数据来源和记录人。

无法取得曝光量时，不用点赞率等需要分母的指标；改用可核验的绝对量和后续业务结果。

## 三、读取与过滤口径

1. 先读取字段 schema，再读取记录。
2. CRM 数量统计必须使用同一快照时间和同一过滤口径。
3. 排除无效、重复、删除和明确不纳入规划的记录。
4. 读取任何记录前先核验其 Base 绑定的 `tenant_id`；多品牌或多账号场景再按账号/负责人过滤，然后计算阶段占比。
5. 阶段为空、值异常或更新时间缺失的记录单独计数并提示。
6. 记录多于单页上限时必须完成分页，只有 `has_more=false` 才能视为完整结果。

## 四、写入边界

- 读取 CRM 不等于允许修改 CRM。
- 只有用户明确要求保存，或已配置并授权自动生成时，才写“朋友圈内容/排期”或“发布效果”。
- 创建“发布任务”或改变审核/发布状态属于独立写操作，不能从“允许保存文案”推导授权。
- 写入前校验目标 Base、Table、tenant_id、日期范围和品牌/账号。
- 更新时只提交变化字段，不替换整条记录。
- 已发布正文、实际效果和历史快照默认不可覆盖。
- 创建或修改表结构必须由用户明确要求。
- CRM 默认只读；聊天分析结果要写回 CRM 时必须单独获得写入授权。

## 五、无法运行时的最小反馈

按下列格式返回：

```text
当前无法生成正式排期/文案。
已识别：<租户、内容工作台、独立 CRM 表、字段>
缺失：<必需字段或记录>
最小补齐动作：<具体操作>
可继续执行的部分：<例如仅做字段映射或资料完整性检查>
```
