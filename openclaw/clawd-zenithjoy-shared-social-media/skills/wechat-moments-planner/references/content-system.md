# layer 1–6 朋友圈内容系统参考

在生成当天朋友圈文案时使用本文件。周规划阶段只参考内容支柱、表达角度和意图，不生成完整正文。

## layer 1：底层逻辑

朋友圈不是“发内容”，而是“跑信任”。每条内容都要帮助读者完成以下至少一个动作：

1. 建立认知：知道你在解决什么问题。
2. 建立信任：相信你确实能解决，有标准、有过程、有边界。
3. 产生行动：在合适的时候咨询、互动或成交。

质量标准：

- 有明确任务：读者看完会更懂、更信或更愿意行动。
- 有对号入座：读者能感觉“在说我”。
- 有可复述观点或可执行方法：读者能带走一句话或一个动作。
- 有证据或边界：不靠口号和过度承诺。

## layer 2：朋友圈内容类型，6 大支柱

| 支柱 | 名称 | 作用 | 对应目标 |
|---|---|---|---|
| p1 | 认知教育类 | 教育市场，让客户知道产品或服务不是噱头 | 建立认知 |
| p2 | 痛点共鸣类 | 打中日常焦虑，拉近关系 | 激发需求 |
| p3 | 方法干货类 | 建立专业度，让别人觉得你懂 | 建立信任 |
| p4 | 案例结果类 | 用结果和过程构建强信任 | 建立信任、促咨询 |
| p5 | 日常真实类 | 建立真实人设，降低陌生感 | 建立信任、养熟关系 |
| p6 | 转化成交类 | 把信任转成咨询和成交 | 促咨询、促成交 |

内容节奏参考：

- 日常养熟约 60%：观点、过程、小干货、共鸣、日常观察。
- 需求唤醒约 30%：痛点、误区、成本对比、场景代入、结果对比。
- 转化推进约 10%：客户案例、成果、服务介绍、招募通知。

## layer 3：8 种表达角度

同一选题可以换角度写，避免重复。

| 角度 | 定义 | 写法提示 |
|---|---|---|
| 场景切片 | 用具体场景开篇，把抽象问题落到细节里 | 用今天、刚刚、现场、动作、对话开头 |
| 对象画像 | 先锁定写给谁，用身份和处境组织表达 | 如果你是……你大概率正在…… |
| 时间轴 | 用之前、转折、之后推动信息 | 起点 → 变化点 → 结果 → 复盘 |
| 决策权衡 | 写成选择题，强调取舍和边界 | a vs b，什么时候选 a，什么时候选 b |
| 反直觉结论 | 先抛反常识结论，再解释为什么 | 真正的……不是……而是…… |
| 标准检查 | 用标准、清单、打分规则表达 | 给 3–7 条判断点，每条说明怎么判 |
| 成本暴露 | 把隐性成本显性化 | 时间、钱、机会、风险、心理消耗 |
| 互动共创 | 邀请读者参与 | 选项、关键词、发材料诊断、评论补充 |

## layer 4：意图 i 执行原则

当生成具体文案时，意图表达遵循：

1. 现实起点：前 2 句出现至少一个镜头元素，如时间、地点、动作、物件、界面、原话、身体反应。
2. 为什么现在说：说明触发原因和代价，不要空泛。
3. 跟读者关系：点名读者身份和具体卡点。
4. 核心判断：先给一句可验证或可执行的结论，再给边界。
5. 最小动作：只给 1 个 10 分钟内可完成且有产出物的动作。
6. 参与方式：只给 1 个明确互动入口，不写泛泛“欢迎交流”。
7. 人格标签：稳定体现落地、讲真话、工程脑、有陪伴感或有锋芒中的一种。

禁止用以下开场：

- 最近我发现
- 我一直在想
- 这段时间

## layer 5：变体皮肤 v

生成每条文案前，在内部选择一个变体皮肤并贯彻，但不要输出选择过程。

每条至少体现：

1. 一个镜头细节：动作、物件、短对话、数字尺度、短对比任选。
2. 一种语言节奏：断句短刀、平静推演、犀利吐槽、温和共情任选。
3. 一种修辞皮相：三连问、排比、类比、反转、极简钉子句、清单化任选。

强制规则：

- 严格沿用既定结构模块与顺序，不新增、删减、重排结构模块。
- 每条关键句式尽量避免与上一条重复。
- 不允许出现“模板、流程、公式、结构”等自我暴露表达。
- 只输出最终文案，不输出 v 的选择、解释、标签或自检过程。

## layer 6：写作公式与模块

完整公式：

```text
上下文（我是谁 × 你是谁） + 变量（p × a × i × s） + v 变体皮肤
```

8 个结构模块：

1. 开头钩子
2. 对象与问题
3. 代价/风险
4. 核心观点
5. 方法/标准
6. 证据
7. 边界与适用条件
8. cta（互动结尾）

模块选择规则：

- p1-p5 可以不写 cta。
- p6 必须写 cta，且只有一个动作。
- 如果缺证据，就一定要补边界来兜住可信度。
- 想让读者立刻行动，至少补代价/风险或证据之一。

默认结构：

| 支柱 | 默认结构 |
|---|---|
| p1 教育/认知纠偏 | 1 → 2 → 4 → 6 → 5 → 7 |
| p2 共鸣/痛点 | 1 → 2 → 3 → 4 → 7 |
| p3 干货/方法 | 1 → 2 → 5 → 6 → 7 → 8 |
| p4 案例/结果 | 1 → 2 → 5 → 6 → 7 → 4 → 8 |
| p5 日常/人设 | 1 → 6 → 4 |
| p6 转化/成交 | 1 → 2 → 3 → 5 → 6 → 7 → 8 |

字数规格：

| 支柱 | 建议字数 |
|---|---:|
| p1 | 120–220 字 |
| p2 | 60–150 字 |
| p3 | 150–260 字 |
| p4 | 120–220 字 |
| p5 | 50–120 字 |
| p6 | 80–160 字 |

段落要求：

- 每段 1 个意思。
- 以 1–2 句为主。
- 长文每 2–3 段至少一次小标题、编号或列表。

常用 cta：

- 诊断式：把你的内容或流程发我，我按标准指出 3 个最该改的点。
- 领取式：想要清单就回我“关键词”，我发你。
- 预约式：想做试点就回我“试点”，我发你路径。

## 成稿边界

- 不编造客户案例、客户原话、数据、成交金额、转化率。
- 不做绝对化承诺。
- 不写夸大收益、夸大效果、确定性结果。
- 不把内部变量、结构或公式暴露给读者。
