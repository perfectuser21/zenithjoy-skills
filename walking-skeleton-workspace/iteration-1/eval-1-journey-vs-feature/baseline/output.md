# AI 自动生成合同条款：挂 feature，不开新 skeleton

## 结论先行

**挂 feature**。这件事应该作为现有合同管理流程上的一个增强功能加入，而不是另起一条 walking skeleton。

## 判断依据

判断"新 skeleton vs 挂 feature"，我习惯看三件事：

**1. 是不是开辟了一条新的端到端用户旅程？**

你的核心用户旅程已经存在：咨询师登录 → 创建/管理客户 → 起草合同 → 发送/签署 → 归档。AI 生成条款不是一条新旅程，它是"起草合同"这一步内部的一个加速器——用户的入口、出口、价值兑现点都没有变，只是中间填空的方式从"手敲/复制模板"变成了"AI 起草 + 人工修订"。这是典型的 feature 增强。

如果你做的是"AI 帮咨询师做客户风险画像"或"AI 自动从邮件抽取潜在客户"——那才是新旅程，值得开新 skeleton，因为它有独立的入口、独立的数据流、独立的成功指标。

**2. 它能不能独立交付价值，且不依赖核心流程？**

不能。AI 条款生成必须挂在合同对象上：要知道是哪个客户、什么类型的服务、什么金额、什么司法管辖区。脱离合同上下文，它就是个 ChatGPT 包装器，没有差异化。这意味着它的成败完全绑定在"合同管理"这条 skeleton 上，独立部署没意义。

**3. 失败时影响半径有多大？**

挂 feature 的好处是：AI 出问题（生成错条款、超时、成本爆炸），可以一键降级回手动起草，主流程不挂。如果你把它做成一条独立 skeleton，反而要重复处理认证、合同存储、版本管理这些已经解决的问题，且降级路径反而更复杂。

## 落地建议

具体怎么挂：

- 在合同编辑页加一个"AI 起草"入口（按钮 / 侧边栏 / 斜杠命令）
- 输入：合同类型 + 关键变量（金额、期限、范围）+ 客户上下文
- 输出：可编辑的条款草稿，**默认进入草稿状态而不是直接保存**
- 必做的护栏：人工确认才能落库、保留 AI 生成痕迹（合规审计）、token 成本上限、明确的免责声明

E2E 验收（按你们项目的 E2E-First 规则）：一个 Playwright 用例覆盖"打开合同 → 点 AI 起草 → 看到草稿 → 编辑 → 保存"——这就是这个 feature 的"完成"长什么样。

一句话：**它是合同流程上长出来的一颗牙，不是另一副骨架。**
