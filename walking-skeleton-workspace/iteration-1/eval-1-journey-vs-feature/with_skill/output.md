# 判断：这是 Feature，不是新建 Walking Skeleton

## 一、明确判断

**"AI 自动生成合同条款" 是一个 Feature，挂在你已有的 Journey（独立咨询师管理客户合同）上的"起草合同"那一步**。它不是一条新的 walking skeleton。

## 二、判断依据（用 skill 的概念框架）

### 1. 价值闭环测试

skill 概念里的核心问题：*"用户走完这一连串动作，他能不能拿到一个完整的、可感知的价值？"*

- 单看"AI 生成条款"这件事：用户输入需求 → AI 吐条款。这本身**不是一个完整闭环**——条款生成出来，没塞进合同、没发给客户、没签字、咨询师拿不到"我服务好了一个客户"的完整价值。
- 它必须依附在原有 Journey（**新建客户 → 起草合同 → 客户审核 → 签署 → 归档**）的"起草合同"这一步，才能产生用户感知价值。

→ 不能独立 demo 一个 5-10 分钟的完整故事 → **不是 Journey**。

### 2. 决策树的"同一个为什么"

决策树问：这个价值跟现有 Journey 是同一个"为什么"吗？

- 现有 Journey 的"为什么"：让独立咨询师**更快更省心地完成一份合同管理闭环**。
- AI 生成条款的"为什么"：让"起草合同"这一步**从手写/复制模板加速到 AI 起草**。
- 完全是同一个"为什么"，只是**某一步的另一种实现方式**（用 AI 替代人工/模板）。

→ skill 概念里写得很清楚："是某一步的另一种实现方式（如用 AI 替代人工）" = **加到已有 Journey**。

### 3. 角色与入口未变

新建 Journey 的三条标准（角色不同 / 价值闭环不同 / 入口出口不同），这个需求**一条都不满足**：用户还是同一个咨询师，入口还是"开始一份新合同"，出口还是"合同签完归档"。

## 三、下一步动作建议

请你回答两个问题，我就可以帮你在 Notion AI Hub 里把这个 Feature 挂上去：

1. **挂在哪条 Journey 的哪一步？** 我猜是"独立咨询师合同闭环 Journey"的"起草合同"这一步——如果你这条 Journey 还没在 Notion 注册，先用 `init journey` 动作建出来（含 5-10 步端到端 path + E2E smoke 路径）。
2. **第一刀做 thin 版本**：默认 thickness = `thin`。建议范围：调一次 Claude API + 硬编码 prompt 拼"咨询类型/客户名/服务范围" 3 字段 + 返回一段纯文本条款 + 复制到剪贴板。**UI 临时、无错误处理、无 prompt 工程、无风格控制**——这些都留给 medium 升级。

注意纪律：本 skill 第 5 条铁律——"新 Feature 默认 thin"。不要一上来就做 prompt engineering + 多模板 + A/B 测试，那是 thick，会让你陷入"单 Feature 完美但 Journey 死亡"的反例。

确认 Journey 名称后，我用 `add feature` 动作给你建条目。
