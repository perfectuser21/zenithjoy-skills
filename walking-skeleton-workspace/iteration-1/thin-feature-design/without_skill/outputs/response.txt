问题：user_facing path 第 3 步"用户填画像诊断"的第一版做什么？

---

先说背景（我查了数据）：

Journey：客户首次成功路径（user_facing）
第 3 步（P1-S3）：画像诊断（行业/受众/风格 3 字段）
当前 Feature 状态：有 1 个旧 Feature "画像表单 3 字段（行业/受众/风格）"，Thickness = thin，Status = deprecated（被废弃）

后端现状：API 已存在且是 active 状态
  - GET /api/profile — 读画像（从 zenithjoy.user_profiles 表读 industry/audience/style）
  - POST /api/profile — 写画像（UPSERT，三字段全必填）

前端现状：完全空白
  - Dashboard 没有任何 Profile / 画像 相关页面
  - App.tsx / navigation.config 没有注册任何 profile 路由

---

第一版（thin）做什么：

做一个 Dashboard 页面，让已登录用户能填写和保存 3 个字段：行业（industry）、目标受众（audience）、内容风格（style）。填完点保存，数据写入后端，页面回显已保存的内容。

就这一件事，不多也不少。

---

具体做什么：

1. 新建页面 ProfilePage.tsx
   - 三个输入框：行业 / 目标受众 / 内容风格（文本输入，不做下拉选项）
   - 页面加载时调用 GET /api/profile，如果已有数据则回显
   - 点"保存"按钮调用 POST /api/profile，成功给提示
   - 401 未登录跳回登录页，正常的错误 toast 提示

2. 在 navigation.config 注册路由 /profile，加到侧边栏（位置放在"设置"或"账号"分组）

3. 写一个简单的单元测试（.test.tsx），测 ProfilePage 渲染出三个输入框

---

不做什么：

- 不做字段校验的复杂逻辑（比如行业下拉选项、AI 推荐风格标签）
- 不做"画像完成后自动跳下一步"的引导流程
- 不做画像数据影响 AI 生成内容的联动（那是 Step 5 的事）
- 不做画像的历史版本、多套画像
- 不做输入长度上限检查以外的任何业务校验
- 不改后端（后端 API 已经够用了）

---

一句话定义完成标准：

用户登录后能在 Dashboard 打开画像页，填写行业/受众/风格三个字段，点保存后数据持久化，下次打开页面数据还在。
