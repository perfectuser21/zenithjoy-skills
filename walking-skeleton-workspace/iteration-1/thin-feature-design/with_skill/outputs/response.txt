## 第一版要做什么

**目标：thin — 端到端贯穿但极其简陋**

thin 不是 demo，不是全 mock，是真跑全链：
- 真实 DB 存数据
- 客户用真账号，填完能存下来
- 后续步骤（AI 生成内容）能读到这份画像

**具体做什么：**

1. **Dashboard 里一个简单的画像表单页面**
   - 3 个字段足够：行业（文本或下拉）、目标受众（文本）、内容风格（文本或下拉）
   - UI 丑没关系，能填能提交就行
   - 不需要校验逻辑，不需要错误提示，不需要加载状态

2. **后端 API 接口**
   - `POST /api/profiles` 或类似路径，把三个字段存进真实 DB（ZenithJoy 数据库，不是 mock）
   - `GET /api/profiles/:tenantId` 能读回来（供后续步骤用）

3. **数据库表**
   - 新建或复用 `user_profiles`（或 `tenant_profiles`）表，存 industry / audience / style 三个字段
   - 写 migration 文件，真跑

4. **和下游打通**
   - 第 5 步"AI 生成内容"要用画像作为 prompt 输入，thin 阶段只需要确认：AI 生成那一步能读到这三个字段值，哪怕是硬编码读法也行

5. **smoke 验证**
   - 有一条命令能证明贯通：填画像 → 存 DB → 读出来
   - 例：`curl -X POST .../api/profiles -d '{...}' && curl .../api/profiles/1`

---

## 第一版不做什么

- ❌ 不做字段校验（必填、格式校验）
- ❌ 不做 UI 美化（颜色、间距、响应式）
- ❌ 不做错误处理（网络失败、重复提交）
- ❌ 不做画像模板、推荐词、AI 辅助填写
- ❌ 不做"诊断"功能（如果"诊断"意味着 AI 分析画像质量，这是 medium 以上的事）
- ❌ 不做多套画像、画像版本管理
- ❌ 不做权限控制（谁能改谁的画像）
- ❌ 不做图表展示、可视化

## 怎么判断 thin 做完了

客户（你自己扮演）能：
1. 打开 Dashboard，找到画像填写页
2. 填入行业 / 受众 / 风格三个字段，点提交
3. 数据存进了真实 DB（能用 SQL 查出来）
4. 刷新页面，数据还在（或者下游生成内容时能读到）

满足这 4 条 = thin 完成。
