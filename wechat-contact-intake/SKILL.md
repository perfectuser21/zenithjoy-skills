# 微信个人与群会话登记

> 候选技能。脚本校验、云手机盘点、人工分类读回和正式部署分别验收；没有同版本真实运行证据时不得标记已验证或启用日常采集。

把微信里的个人与群登记为沟通渠道，再关联客户／项目。客户主档独立于微信账号和群；同一客户可关联多个私聊和群，一个群也可关联多个客户。群成员不会因为在客户群里自动成为客户。

## 输入和执行边界

读取当次私有运行绑定中的 `tenant_id`、`wechat_account_id`、预期账号、设备序列号、控制器、证据目录、`runtime_root` 与固定 `source_revision`。原始姓名、群名、截图、分类文件和数据库留在该租户的私有工作面，不进入 Git、共享日志或群消息。证据查看使用当前执行环境的原生图片工具，不额外发往 OCR 或第三方模型服务。

业务实现位于 `perfectuser21/zenithjoy-workspace` 的 `services/wechat-contact-inventory/cli.py`；技能目录不复制执行代码。开工先核对运行包的固定提交及清单哈希、运行 `--help`，按 [输入输出合同](references/runtime-contract.md) 核对版本。环境、账号、实现版本或输入合同不符即停止，不以浮动分支或另一个租户替代。

手机动作复用现有通用微信 Phone 控制器及公共设备锁。`wechat-cs-android` 的工具要求已领取客服事件，不能为扫描伪造通知事件借用它。盘点授权不包含发送、自动回复、加好友、拉群或改变群设置。

## 首次盘点与增量重扫

| 阶段 | 前置 | 动作 | 完成判据与证据 | 失败处理 |
|---|---|---|---|---|
| 核实账号 | 私有绑定、固定运行包和明确盘点授权齐全 | 领取本次设备租约及公共锁；预检在线、通话空闲、屏幕状态；用受控工具读当前微信账号 | 原图／UI 树中的账号与绑定一致；锁 owner 属于本次 run | 锁忙、登录或账号不符停止；不抢锁、不切账号 |
| 盘点个人和群 | 账号已核实；当前页面可辨认 | 用现有控制器从实时控件／原图导航，读取实际可见的个人联系人和群会话；记录每页证据及可核实身份 | 每个观察对象有本 run 原图／UI 树来源；个人与群分别标注；实际覆盖及未覆盖范围已记录 | 同名歧义保留独立待确认项；读不到不猜 ID，不用群名／昵称合并；未完成时报告部分覆盖 |
| 登记待分类 | 盘点清单符合合同，证据可读取且摘要一致 | 调用 `ingest`；从回执取得 `account_key`，再调用 `export-review` | 新对象为待分类，采集与回复开关均关闭；重扫保留已有人工标记；导出可审阅 JSON／CSV | 合同、身份或证据冲突停止，保留原数据，不调用旧版默认 customer 的 friend-scan 入库接口 |
| 归位 | 盘点已结束或遇到停止条件 | 按当前已确认页面逐步退出敏感界面，释放自己持有的锁并读回 | 原图／控件证明归位；锁释放后读回 free，或明确报告其他合法 owner | 不释放他人锁；无法核实归位时报告 cleanup_pending |

账号登录页、未核实账号或预检不通过时，运行状态为 `blocked`，记录现场原因与证据，不生成零联系人成功盘点。真实盘点入账且审阅产物可访问后交接为 `awaiting_review`；用户尚未确认的记录保留待分类，不能由 Agent 代造批准。

首次盘点不等于历史聊天全量采集。只看到近期会话时写 `visible_excerpt` 和 `complete=false`，逐项说明未覆盖的通讯录、未显示的群、历史消息等。日常重扫也只登记本次实际观察对象；某页没看到不能据此删除或停用已有联系人。

只有实屏核验的稳定微信 ID／群 ID 能跨 run 归并。拿不到稳定 ID 时保留临时观察项；临时项不能启用采集。后续确认身份须通过可追溯的关联流程，不直接改 ID 或按名字猜同一人。

## 人工分类读回

向用户提供该账号的 `export-review` 产物及其实际可访问位置。当前工作面是私有 JSON／CSV；没有已验收的写回适配器时，不声称在 Notion 改分类就会自动回流，也不另建一套任务账。

人工逐项确认个人或群为客户、内部、私人、排除或待分类，并填写真实客户／项目引用。保留人、群、客户的不同身份；客户群可有多个 `customer_refs` 和 `project_refs`，项目可空但客户归属不能凭群名猜。分类、`collect_enabled` 和 `auto_reply_enabled` 独立；本流程不接受开启自动回复。

仅导入用户实际修改并确认的分类产物，调用 `apply-review --actor` 时记录真实操作者，不由执行 Agent 为用户代填确认。回读更新后的导出，核实 record、revision、分类和开关。任一条过时、跨账号或不满足对应采集门槛时先处理冲突，不覆盖人工新值、不部分导入后宣称整批完成。

## 增量采集门禁

调用 `eligible` 得到本账号可采集对象及拒绝原因。只有人工确认的客户、具有已核验稳定身份、客户引用齐全且明确启用采集的对象才可出现在可采集列表；其余保持排除。人工撤销采集应在下一次门禁中立即生效。

`eligible` 只生成采集计划，不读取消息、不运行客服或发布器。实际消息采集器须另外核对同一租户、账号、对象和本次授权，并按各消息的来源、群及发言人保存证据。没有已验收采集器或明确运行授权时，仅报告计划，不把计划算作已采集。

## 验收与交付

验收逐项读回，不以脚本 exit 0、目录 active 或有任务 ID 代替业务结果：

- 同一 run 的真实个人／群观察及覆盖范围可查，账号一致，证据摘要可复算。
- 新记录均待分类且两个开关关闭；重放同一清单无重复，重扫不覆盖人工分类；未知身份不按名字归并。
- 人工确认后，重新导出的分类、引用和开关与本次确认一致；过时 revision 被拒绝；`eligible` 仅包含满足门槛的对象。
- 设备归位和锁释放有独立读回；发送、加好友、群设置变更和自动回复动作均为零。

交付 `run_id`、运行包 revision、账号脱敏标识、覆盖范围、个人／群观察数、新增／已存在／临时项数、待分类数、分类回执、可采集／拒绝数、证据位置、`cleanup_status` 和实际副作用。按「盘点已完成／分类待人工／采集尚未运行」分别报告，不合并成一个成功状态。由独立核验者对同 run 证据判定后，才能更新验证状态。

## 契约

- 前置：已授权账号与盘点范围、匹配的私有绑定、可用受控 Phone、fresh 锁、固定且已校验的 runtime、可写私有状态目录。
- 后置：本次观察可追溯入账；分类与采集计划可回读；成功范围不超过实际覆盖。
- 副作用：读取微信页面，在私有 SQLite 和审阅产物中记录渠道及人工分类；手机导航可能改变已读状态，应据实记录。没有发送或接管副作用。
- 失败模式：设备／账号不符、读取失败、覆盖不完整、身份不明、摘要不符、跨账号输入、过时分类 revision、已有人工更改、无可采集对象；分别报告，不自动扩范围或回退旧接口。
