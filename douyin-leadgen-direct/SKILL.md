# 获客 Skill 直接执行

由当前 Codex 会话读取业务方法、观察工具结果并决定下一步。启动脚本只领取 Brain 任务、提供工具环境、启动 Codex 和收集回执。手机控制、解析、持久化、去重等确定性操作继续使用已有工具。

适用于用户明确选择本模式的新任务。已有旧运行先确认真实终态和资源归属，不能用新会话接管未知执行者。

## 执行

1. 读取 Brain 任务的 task_id/run_id、阶段、公司/租户、输入范围、数量、业务截止、收尾截止和授权；原子领取。缺少影响执行的输入时从该公司已启用配置取，仍缺再询问。
2. 固定本 Skill 和工具路径/版本/摘要，保存本轮上下文。按[工具合同](references/tools.md)核真实接口。文档中有名称不等于工具已可调用。
3. 读取并执行目标阶段的方法：

| 阶段 | 方法 | 交付 |
|---|---|---|
| 101 | [视频发现](references/101.md) | 视频ID、链接、同视频指标与持久读回 |
| 102 | [视频处理](references/102.md) | 资格、评论与原生身份、提交读回 |
| 103 | [评分与线索](references/103.md) | 原政策评分、线索和配送真实状态 |
| 104 | [授权触达](references/104.md) | 原订单的一次发送与写回证据 |

4. 每次调用后读取真实结果，按现场和剩余预算选下一步。由 Codex 执行步骤，不调用整段工作流启动器代替本轮业务。prepare、绑定、单次手机动作和单次数据事务是工具，不承担流程决策。
5. 收尾、独立读回，再向 Brain 提交回执。保存业务run与Codex执行run的对应关系；独立Skill首跑不冒充旧完整工作流版本验收通过。

## 四步组合

101视频交102；102已提交评论可由103独立消费；103合格且交付确认的订单进入已授权104。各阶段保留自己的范围、数量和截止，前一步成功不扩大下一步授权。只要求101时完成其交付和清理即结束。

恢复从持久读回开始。已完成视频、已提交评论、已发送动作保留原身份；外部结果未知先核对，不换run重做。手机阶段持有真实中央租约和本地锁，103不占手机。

## 验收和回执

逐项给出业务完成情况、实际数量、原件与持久读回、停止原因、工具实际用量、模型与视觉外发计数和资源收尾。空队列、限额、unknown、缺接口分别记录；模型自述和进程退出0不能替代业务验收。

Brain是任务和运行真身。任务页和执行页由正规投影生成，分别读回Notion目标ID、所属库、任务/run对应关系和最终状态。未同步标notion_terminal_pending，不直接编辑投影补绿。

输出JSON至少含task_id、run_id、stage、execution_mode、status、business_pass、counts、artifacts、readback、cleanup、notion、remaining_gaps；真实业务输出另附源ID。status=completed需要阶段后置条件及收尾全部可证实。

## 数据外发

API Codex 会把本轮输入、工具结果及其读取的截图发送给 OpenAI 完成本轮判断。已有手机控制器在无障碍树无法定位筛选或视频页签时，可能经 `locate-element.py` 将截图及定位描述发送到 OpenRouter 的配置模型。独立入口固定 `ZJ_EXTERNAL_LEDGER`，每次实际视觉 HTTP 请求先记 intent、结束记 returned；失败和拒绝也分别保留，无法记账时禁止发送。按 request_id 统计真实外发次数，并与 Codex 模型用量分别回执；缺账不得默认填0。凭据只留工具宿主，不进入模型输入或回执。

## 契约

- 前置：任务授权并领取；公司政策、工具来源和资源可核。手机阶段核实际账号、通话、设备；104另核目标、准确话术和额度。
- 后置：阶段业务产物、同租户持久读回、真实停止原因和本人资源收尾齐全。Notion记录存在与终态正确分别验收。
- 副作用：101/102导航和本公司采集数据写入；103评分、线索及原配送outbox；104批准的一次发送；各阶段写任务/运行回执和证据。
- 失败：工具缺失、来源不符、设备/账号不符、锁冲突、风控、写入或外部结果未知、预算耗尽、投影滞后。保留证据，准确交付partial/blocked/failed。
