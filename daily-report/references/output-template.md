# 输出模板：客户日报两层日报

使用本模板输出按客户名称读取资料后生成的客户日报。默认必须先输出“本次分析资料范围”模块，再采用原有“两层日报”：先为每个客户生成单客户当日日报，再基于每个单客户日报生成所有客户当日总结日报。

## 强制输出总规则

1. 多客户场景默认不得只输出总结性日报。必须先输出“第一部分：单客户当日日报”，再输出“第二部分：所有客户当日总结日报”。
2. 单客户当日日报是汇总日报的基础。汇总日报中的阶段分布、高优先级客户、突出机会、突出风险、明日动作，都必须来自前面已经判断过的单客户日报，但汇总日报不得复制单客户日报完整内容。
3. 每个客户都必须有自己的单客户日报，即使客户暂时不重要、信息很少、只适合观察，也不能只放到总表里。
4. 每个客户的单客户日报必须单独包含“当日突出点”字段，不得只在所有客户总结日报里体现。
5. 单客户日报要简洁，每个客户控制在 11-13 个字段；客户很多时，不扩写成长篇，但不能省略必要判断。
6. 所有客户当日总结日报面向老板/团队复盘，强调总览、机会、风险、卡点、优先级和团队动作，必须短、快、可扫读。
7. 用户只给 1 个客户时，只输出单客户当日日报，不输出总结日报，除非用户明确要求汇总。
8. 用户明确要求“只要汇总/只要总表/不要逐客日报”时，才可以跳过单客户日报。
9. 用户明确要求“详细分析、完整分析、逐客户展开、验收、eval、对比”时，使用详细模板或评分表。
10. 每个客户必须保留核心判断：阶段、推进信号、询价类型、阶段依据、当日突出点、变更记录、主缺口/最大阻力、适配风险、下一步动作、建议回复、内部记录。
11. 下一步动作必须具体到动作、时间或条件、资料或边界，不能只写“继续跟进”。
12. 遇到明确推进信号，优先写收口动作；遇到弱信号或调研型询价，先确认意图，不强推付款。
13. 遇到要求保证结果、拒绝配合、拒绝边界的客户，必须标注高风险或暂不适配。
14. 缺失信息写“未体现/待补充/暂无法判断”，不得编造产品名称、价格、承诺、案例、合同或交付周期。
15. 所有客户总结日报默认只保留 4 个部分：今日总览、当日突出点、明日重点任务、团队话术/物料提醒。
16. 默认不输出“客户跟进清单/压缩管理看板”。单客户日报已包含执行信息，汇总日报避免重复变长。
17. 只有用户明确要求“客户跟进总表、压缩看板、全量客户状态表”时，才在 4 个默认部分之后额外输出附加表。
18. 当本周日报、本月周报、客户月报或客户档案已纳入分析时，单客户日报必须输出“变更记录”，不得重复判定历史已有结论，只记录今天相对最近日期有效资料的变化。
19. 正式日报正文前必须输出“本次分析资料范围”模块；该模块必须包含“当日状态”，并列明每类资料是否已纳入分析、未提供或待补充。
20. 资料内容存在冲突时，以最近日期资料为准；日期相同但冲突时，标注“待核实”。

## 可下载文件输出规则

当用户要求将日报转换为 HTML、Word、PDF、Markdown 或其他可下载文件时，必须遵守“单客户单文件”原则：

1. 每个客户的单客户当日日报必须独立生成一个文件，不得把多个客户的单客户日报合并在同一个文件或同一个页面中。
2. 所有客户当日总结日报必须单独生成一个汇总文件。
3. 如需提供导航，可额外生成 `index.html`、目录页或总目录文件；目录页只做链接索引，不替代单客户日报。
4. 文件命名建议采用：`01_客户名_单客户当日日报.html`、`02_客户名_单客户当日日报.html`、`99_所有客户当日总结日报.html`。
5. 除非用户明确要求“合并成一个文件”，否则默认按单客户单文件输出。用户要求合并时，也必须在合并文件中清晰分隔每个客户的独立日报，并保留每个客户的“当日突出点”。

## 第一部分：单客户当日日报

> 每个客户都输出一份。目标是沉淀“今天这个客户怎么判断、今天最突出什么、怎么跟、发什么、何时跟”。

### 客户：<客户名>

| 字段 | 内容 |
| --- | --- |
| 当前阶段 | <A1/A2/A3/A4/证据不足；必要时写置信度> |
| 推进信号 | <有/无/不明显；强推进/弱推进/无推进；是否应收口> |
| 询价类型 | <购买型询价/调研型询价/模糊询价/不涉及询价> |
| 阶段判断依据 | <客户原话或聊天事实，1-2 条> |
| 当日突出点 | <1-3 条；写今天该客户最重要的机会/风险/变化/卡点/动作> |
| 变更记录 | <有历史材料时写 1-3 条：变更项、变更前、变更后、变更原因、证据、动作影响；无历史材料写“首次记录/无历史基线”> |
| 主缺口/最大阻力 | <确认感/安全感/信任感/结果感 + 一句话说明> |
| 适配风险 | <正常/谨慎推进/高风险/暂不适配 + 理由> |
| 下一步动作 | <对象+动作+时间/条件+资料或边界> |
| 建议回复 | <可以直接发给客户的一小段话；不超过 120 字> |
| 内部跟进记录 | <阶段、顾虑、已推进动作、下一步、风险，一句话写完> |

单客户日报填写要求：
- “阶段判断依据”必须来自聊天记录，不能用销售主观期待替代。
- “推进信号”必须写强弱和是否收口。
- “询价类型”只在客户问价格、预算、付款、费用时判断；没有询价写“不涉及询价”。
- “当日突出点”必须写在单客户日报中，不能只写到汇总日报；建议写 1-3 条。
- “当日突出点”必须基于当天聊天记录，可覆盖突出机会、突出风险、突出变化、突出卡点或突出动作。
- “变更记录”用于后续查询客户状态为何变化；有历史材料时必须写清变更前后和原因，没有历史材料时写“首次记录/无历史基线”。
- “建议回复”默认必须给出，因为单客户日报服务于跟进执行。
- “内部跟进记录”用于后续日报、周报沉淀，不写聊天流水账。

当日突出点示例：
- 突出机会：客户主动提交资料并预约复盘，属于强推进信号。
- 突出风险：客户明确只做预算调研，不接受约会和催付款。
- 突出变化：客户从低价体验进入资料补齐和诊断复盘阶段。
- 突出卡点：客户当前最担心合同范围和后续需求蔓延。
- 突出动作：今天应优先发送启动清单和角色分工表。

## 第二部分：所有客户当日总结日报

> 基于第一部分每个客户日报汇总，不重新判断，不新增前面没有依据的新结论。

### 1. 今日总览

- 客户总数：<数量>
- 阶段分布：A1 <数量>、A2 <数量>、A3 <数量>、A4 <数量>、证据不足 <数量>
- 高优先级客户：<数量及客户名；没有写“无”>
- 今日可收口客户：<数量及客户名；没有写“无”>
- 高风险/暂不适配客户：<数量及客户名；没有写“无”>
- 今日主要成交阻力：<用一句话概括最集中的阻力>
- 明日最重要动作：<用一句话写清明天第一优先级>

### 2. 当日突出点

> 只写今天最值得老板/团队一眼看到的 3-5 条，不写流水账。必须来自单客户日报中的“当日突出点”和核心判断。

- 突出机会：<哪些客户出现明确推进信号、可收口到付款/预约/提交资料/签约>
- 突出风险：<哪些客户要求保证结果、拒绝配合、只调研不启动、阶段证据不足>
- 突出变化：<客户从观望变问价、从问价变提交资料、从意向变拖延等>
- 突出卡点：<多数客户卡在价格安全感、结果验收、决策链、时间配合等>
- 突出动作：<今天销售最该补哪类物料、改哪句收口话术、明天先跟谁>

### 3. 明日重点任务

> 本部分按团队任务主题聚合，突出明天最该先处理的 3-5 类动作。不要按客户逐行重复单客户日报里的“下一步动作”。

| 优先级 | 明日重点任务 | 涉及客户 | 目标结果 | 注意事项 |
| --- | --- | --- | --- | --- |
| 1 | <例如：完成强推进客户收口> | <客户名1、客户名2> | <希望这些客户共同完成什么结果> | <不要踩的坑/需补物料/边界提醒> |

填写要求：
- 默认最多列 3-5 个“任务主题”，不要按客户逐行复述单客户日报的下一步动作。
- 动作相近的客户必须合并，例如“强推进客户收口”“A1 防御客户低风险触达”“高风险客户边界确认”“调研型询价轻触达”。
- “涉及客户”可以写多个客户；没有对应客户时写“无”。
- “目标结果”写团队希望达成的阶段结果，不写聊天记录依据。
- “注意事项”写话术边界、物料准备、不要做的动作。
- 只有当明日真正只有 1 个关键客户，或用户明确要求逐客户列明日动作时，才可按客户输出；即便如此，也不能复制单客户日报“下一步动作”的原句。

### 4. 团队话术/物料提醒

- 今天话术问题：<只写 1-3 条，如没有明显问题写“未发现明显共性问题”>
- 明天建议补充物料：<只写最需要的 1-3 个物料>
- 今日不要做：<例如不要把调研型询价当购买型询价、不要对高风险客户承诺结果>

> 默认到此结束所有客户当日总结日报。不要再输出“客户跟进清单”或“压缩管理看板”；用户明确要求时，才作为附加表放在本部分之后。

# 逐项能力评分表（仅在用户要求 eval、验收或 Skill 对比时输出）

正式 Eval、验收或 Skill 对比时，不使用主观分值评分，必须按以下文件执行：

- `references/eval-v2-sop.md`
- `references/eval-v2-scorecard.md`
- `references/eval-v2-golden-answer-template.md`

Eval 报告必须包含：
1. 测试类型、样本数量和样本覆盖情况。
2. Baseline 0、Baseline 1、Skill Run 的定义。
3. 二值断言评测表。
4. 关键失败项检查。
5. 2-3 个典型客户效果证明，具体说明 Skill 好在哪里。
6. 是否通过、是否可上线、下一次回归建议。
