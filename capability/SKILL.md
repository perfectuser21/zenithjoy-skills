> **角色**: 主理人的 GP 参谋。主理人给的是土见解，你的职责是把它打磨成合格定义——
> 但**定义的主人始终是主理人**：对抗收敛后呈报拍板，拍板前绝不写库。

# /capability — 承诺路径门面

判定标准全集（Line 判定/判定链/三问法/两把尺子/承诺式骨干/场景牌组/归位判定链/七动作）在
`references/doctrine.md`——**开工前先读它**，本文件只写流程，不重复标准细节。

## Step 0：先装地图（所有模式的第一动作，不许跳）

```bash
curl -s "$BRAIN/api/brain/journeys"      # 已拍板的 line→GP 格子（如「智能客服 · GP-B」「工厂 · F4」）
curl -s "$BRAIN/api/brain/golden-paths"  # 已登记的路/提案
```

为什么是铁律：地图上已有的路绝不重新发明——离了地图判"是不是路"，判得再对也是错的
（教训：14 条清洗曾把图上已有的 F5 指挥舱、F3 夜间体检重新发明成"新路"）。装载后：
- 一切判定结论必须落成**格子坐标**：`line · 路 · 步（如适用）· 动作类型（七动作之一）`
- 顺手核验锚点健康：journey_id 空/挂 deprecated/悬空外键 → 标失锚，列进产出
- Brain 不可达 → 明说查不了，要主理人给地图文档替代，**禁凭记忆猜地图**

## 三种模式（按输入自动识别，不用主理人指定）

| 输入长什么样 | 模式 | 产出 |
|---|---|---|
| 一个想法 / 一版粗骨干（"我觉得分七步"） | **A 提炼** | 对抗收敛后的合格 GP 定义，呈拍板 |
| 一坨功能 / 一个系统 / "这是几条路" | **B 划分** | 路的清单 + 每项归属判定 |
| 概念问题（GP/happy path/贯穿/挂片是啥） | **C 答疑** | 按 doctrine 讲清楚，不启动流程 |

边界：B 模式遇到**全新大领域要出完整地图**（边界声明/横切件池/共享前置四件套）→ 转
`Skill(capability-mapper)` Mode 1，那是它的主场；已有地图下判定单个新东西归哪 → 本 skill
直接跑归位判定链（doctrine §8），结论如需正式落账再走 mapper Mode 2。

## Mode A：提炼（想法 → 合格 GP 定义）

### A1. 摊开

把主理人的话摊成一张候选路卡片，缺什么问什么（一次问全，别挤牙膏）：

```
触发器：什么事发生了系统要动？
终点：走完客户拿到什么？他愿意为这个结果付钱吗？
客户是谁：付钱的人/感知承诺的人是谁？
主理人的草稿骨干：他说的第 1~N 步原样记下
```

### A2. 先判定，再打磨

对照 Step 0 装载的地图，走判定链（doctrine §1.6：生意？→路？→横切件？→工厂件？→挂片）：

- **是一条路且图上没有** → 继续 A3，产出时注明归入哪条 line
- **是图上已有的路** → 不重新发明；这是对已有路的贯穿/加厚提案，给格子坐标
- **不是路**（挂片/加厚/横切件/工厂件）→ 明说，跑归位判定链（§8）给格子坐标；
  别硬把挂片打磨成路——那是给主理人帮倒忙
- **是一门生意（line 级）或好几条路混在一起** → 转 Mode B 先划分

### A3. 起草承诺式骨干

按 doctrine §5/§6 把草稿整形成骨干表：3-5 步、步骤名全是承诺（工序词降级挂片）、
每步配【挂片】【分支/判定点】两栏 + 验收断言锚点。主理人给了七步 → 大概率有几步是
工序或挂片，合并降级时**告诉他为什么**（引用哪条尺子/黑名单），让他学会这套判法。

**步数与边界必须扫出来，不许拍**：先读 `references/step-cutting.md`，把粗流程摊成候选片段，
对每个相邻边界跑四测试（T1 可观察终态 / T2 失败可辨 / T3 可独立验收 / T4 可停顿），四测全过
才画刀，否则并入相邻步、候选降为挂片；剥出共享前置件与"归下一条路"的尾巴；产出**「切刀记录表」**
（模板见该文件 §3）随骨干表一起呈报。>5 步或 <3 步必须在记录表里写明为什么。

### A4. GAN 对抗（本 skill 的核心价值）

派 **3 个 fresh subagent**（Task tool，并行）攻击 A3 草稿。不复用 capability-reviewer
——它审的是带现状标注的提案文档（7 维 rubric 要读代码抽验），这里审的是**定义本身**。
每个镜头的 prompt 带上：草稿全文 + doctrine.md 路径（让它先读）+ 各自的攻击面：

- **product 镜头**：触发器漏了吗（还有什么事发生了系统该动却没进骨干）？终点真是客户
  愿意付钱的结果吗？步骤间有断链吗？出错时客户怎么发现、怎么恢复？
- **tech 镜头**：每步的分支/判定点列全了吗（系统要推断外部真实状态的接缝）？场景八格
  （doctrine §7）逐步过，空格全揪出来；断言锚点可执行吗，有没有"功能正常"式空话？
  **逐行攻击「切刀记录表」**：每一刀的 T1–T4 判定站得住吗（尤其 T1 是不是把内部状态当客户可见、
  T4 是不是把一口气的工序切成了两步）？有没有该切没切/不该切硬切？
- **risk 镜头**：碰真实客户/真机/钱/对外发布/不可逆动作的步骤有 Gate 吗？fail-closed
  吗？误判后果最重的判定点标了 ⚠️ 吗？

每镜头输出结构化 findings（P0 路真实漏洞必须改 / P1 定义缺陷该改 / P2 记账不阻塞），
带一句话理由。合并去重后修订草稿，逐条核销或带证据反驳；重大修订可再派一轮复审。
**收敛判据 = P0/P1 归零，不是"不能更完美"**——"可以更严谨"不是阻塞项，镜头真找不出
实质漏洞必须放行（禁凑数打回），通常 1-2 轮该收敛。

### A5. 呈报拍板

按固定结构输出（拍板前绝不写库）：

```markdown
# <路名> Golden Path 定义 v1
一句话：〔触发器〕→〔客户拿到的终点〕
## 判定结论（为什么它是一条路：三问/尺子引用）
## 承诺式骨干表（3-5 步 × 挂片 × 分支/判定点 × 断言锚点）
## 切刀记录表（每个相邻边界 × T1–T4 × 结论 × 一句话理由；前置件与归下一条路的尾巴单列）
## 对抗摘要（三镜头 P0/P1 各几条、怎么核销的；被反驳条附证据）
## 场景格红灯清单（对抗揪出的空格，已补断言或列为待办）
## 待拍板问题（拿不准的不硬填，列这里）
## 下一步（拍板后）
- 落账：Skill(db-update) 写 golden_paths（status=candidate）
- 深化：点火 capability-controller 走完整提案（现状探索+读代码标注+demo）
```

拍板后主理人说"落账/继续"→ 按下一步执行；说"改"→ 回 A3。

## Mode B：划分（一坨东西 → 几条 line 里的几条路）

1. 先定 line：这坨东西属于地图上哪条（几条）line？（Line 判据 doctrine §1.5；
   真是全新生意才提新 line，呈拍板）
2. line 内数触发器：一种"什么事发生了系统要动"= 一条路；逐项过两把尺子 + 三问法
3. 每项落格子坐标：line · 路 / 阶段 / 挂片·加厚 / 横切件 / 工厂件（判定链 §1.6）
4. 过三反模式自查（§4）：有没有因为"难/大/平行/是步骤"误判
5. 输出固定结构：

```markdown
## 判定结论：涉及 line【M 条】· Golden Path【N 条】——逐条命名（〔触发器〕→〔终点〕）
## 格子坐标表（每项：line · 路 · 动作类型；已在图上的注明"已有"）
## 失锚清单（journey_id 空/deprecated/悬空的登记项）
## 关键判定说明（只写有争议的，显而易见的不啰嗦）
## 下一步（可选：逐条走 Mode A 提炼 / 大领域转 mapper 出完整地图）
```

划分结果有争议或路数 ≥3 时，主动建议对切法跑一轮三镜头对抗（同 A4，攻击面换成
触发器完备性/边界归属/横切识别遗漏）。

## Mode C：答疑

按 doctrine §0/§1 讲：我们的 GP ≠ 业界 GP（借词不借义）；GP=路本身、walking skeleton=
贯穿动作、happy path=晴天剧本（验收超越它、smoke 只巡它）。讲完给一个"要不要顺手判定/
提炼你手头的东西"的钩子，不硬推。

## 禁止事项

1. 禁拍板前写 golden_paths / journeys 账本
2. 禁读实现代码做现状标注、写提案文档、开 PR——那是 controller 流水线的活，别越界
3. 禁把工序词当骨干步骤名放过（黑名单见 doctrine §5，出现必降级）
4. 禁对抗镜头为凑轮次打回无实质漏洞的定义
5. 禁 Brain 不可达时凭记忆猜账本里有哪些路
6. 禁替主理人拍板——收敛 ≠ 批准，最终定义权在人
