# HTML 动态演示网页（HTML-as-PowerPoint）

给客户**现场演示或发链接**的单文件 HTML 演示。目标「有质感、可交互、不花、不素、不乱、不死板」。以下是**几十轮真实返工**踩出来的死规范——尤其看 §二/§三/§五/§十一，这几条是反复被否才定下来的。

## 一、骨架（固定）
- **单文件 HTML**：自带 doctype/html/head/body，CSS/JS 全内联，图标用内联 SVG `<symbol>` sprite，图片/logo 用 data-URI。零外链（离线/CSP 都要能放）。
- **左侧栏 nav + 右侧 stage**。nav 项 = **序号 + 名称，不放 icon**（用户明确嫌 nav 图标丑，只要 `01 公司·信任`）。当前项 = **实心品牌蓝 pill**（不是淡底+竖条，那个"悬空蓝条"被否）。侧栏可汉堡收起。**绝不出现重复条目**。
- **页面 = section.page**，一次显示一页，`display:none/active` + 淡入；右下角「上一页/下一页」pager；顶部进度条 = **干净的实心蓝细条**（别用蓝→青渐变，会像"彩虹线"被否）。
- 每页：`eyebrow(小标签,可带 icon) + h1(一句话大标题) + lead + 内容`。留白充足。
- 键盘 ←/→ 翻页 + View Transitions 翻页过渡 + 逐元素错峰入场，都加上（低成本、显高级），全部 `prefers-reduced-motion` 降级。

## 二、视觉 —— ⭐最终定稿配色（反复被否后定的，别再乱试）
经历过 默认蓝 / autopilot 暗色 navy / 暖纸编辑 / 电靛前沿 全被否，**最终锁定 = 深色 navy 侧栏 + 蓝白主区**：
- **侧栏整条 navy**：`background:linear-gradient(180deg,#20366b,#131e3b)`；右缘加投影 `box-shadow:5px 0 28px rgba(15,23,45,.16); z-index:6` 软化和白主区的接缝（不软化会显"两块不搭"被否）。白 logo 直接嵌进 navy 栏（见 §九），**不要孤立的小徽标盒子**。
- **主区蓝白**：`--bg:#eef2f9`（比纯白略偏蓝，和 navy 同色系呼应）、`--surface:#ffffff`、`--ink:#10203a`、`--slate:#55647a`、`--muted:#93a1b6`、`--line:#e7edf6`、`--line-soft:#f1f5fb`。
- **主色 accent `#2563EB`**（autopilot 同款）、`--c-tint:#eaf0fe`、`--c-tint2:#d9e5fd`。辅色青绿 `#10eaa9` 只在极少渐变点缀（别多）。
- **单一主色 + 中性灰，禁止彩虹**。深色元素（如封面"客户问"标签）别用纯黑，用蓝，跟主色统一。
- **不用 emoji**。icon 要**扎实一点**（stroke 2.0，别 1.8 那种单薄）；重点 tile 用**实心蓝渐变 + 白 icon**（app 图标质感，比"淡蓝底+蓝线 icon"高级）。
- 卡片：三档阴影 sh-sm/md/lg + 圆角 + hover 微上浮；发丝级 hairline 边框。别扁平到"太素"，也别堆到"太乱"。

## 三、交互 & 版式 —— ⭐三 tab + 版式多元（这两条被反复要求）
- **三个 tab（不是两个）**：`讲解 | 示例·怎么填 | 对比`。
  - **讲解** = 概念（这项资料是什么 + AI 怎么用它）＋点字段→右侧详情实时更新。**别把"缺vs有对比"混进讲解**（混一页被否，说"很怪"）。
  - **示例** = 填好的完整范例 + ✗→✓ 写法对比 + 要点。
  - **对比**（独立 tab）= 一张对比表：`资料项 | 缺这项·AI 答成什么样 | 有了它·AI 具体怎么答`。这张表既是核心理念载体（§五），又是一种版式变化。
- **版式必须多元，不能每页都"左右左右"**（反复被否"太死板"）：混排——有的页左右分栏、有的页**上下式**（宽图表/时间轴整幅在上、内容在下，`.detail.stacked` 单列）、对比 tab 是表格。同一套翻页/交互语言下让版式有节奏变化。
- **别硬加图表**（曾加雷达图被否"感觉强行在加"）：图示要真的贴内容才放，否则宁可不放。
- 封面放**三态对比**（人工 / 通用AI / 悦升AI），副标强调「同款 AI · 没喂资料」vs「同款 AI · 喂了六项资料」——**差别只在资料**，只有赢家用主色高亮。

## 四、图示按内容配（别模板化、别每页 iPhone）
- **iPhone 聊天样机**：只用在"客户对话/异议"页。要**正经对话**：客户问在右（蓝气泡）、AI 答在左；比例固定 ~2:1 竖屏（屏幕定高别变形）；头像用**品牌 mark**（navy 圆底+白标），别用通用 spark 图标。
- **条形/四维图**：价值评分（可挂「提分方向」告诉客户怎么把分提上去）。
- **画像卡 / 字段卡**：客户画像、知识库档案条目。
- **时间轴 / 路线图**：阶段 A1–A5（注意别和详情里的时间轴重复，重复被否）。
- **证据卡 / 对比表**：案例、多条目对比。

## 五、卖点：资料的价值（但**别做成死板公式**）
- 核心卖点是**"我们的六项资料库如何改变 AI 的回答"**——不是秀模型本身强、更不是贴客户业绩 KPI（贴"华森前后达标率 68%→96%"这种业绩表被否：跑题+无法证明+主体混乱）。
- ⚠️**"缺资料 vs 有资料"的对比不是必做，更别每页统一成一张红蓝对比表**——用户明确说这个"不那么重要、我也不喜欢、也很死板"。想体现资料价值就**换着法子来**（这页用对话、那页用字段卡、另一页用图示/表格），**绝不公式化套到每页**。
- 收尾「为什么正好这 N 项」：必要/足够/够深 三支柱。

> 🔑 元教训：**"死板"是这位用户的头号雷区**。任何"解法"（对比表、雷达图、左右分栏、某种版式）一旦被**统一套到每一页**就变死板、就会被否。正解不是"找一个好模板复用"，而是**每页当独立作品设计**——版式、图示、信息组织都尽量不一样，只保留导航/交互语言一致。宁可慢，别套模板。

## 六、内容规范（字段/例子/诊断）
- **用甲方自己举例**（悦升云端做 AI 智能客服/获客/私域），**别用虚构第三方**（"华森清洁"被否："这明显是我们自己的，举自己的例子"）。
- **讲解字段 ↔ 示例字段必须对齐**（字段数一致、顺序一致）。缺字段会显"突兀"被否。公司六项标准字段：公司名称/所在地区/服务区域/联系方式/业务定位/营业资质/服务流程/售后方式。客户画像字段：年龄/性别/地域/行为兴趣/消费能力/当前问题/购买动机/实际使用人/付款人。案例字段含：案例名称/客户阶段/案例背景/使用方案/解决过程/实际结果/客户反馈/可公开范围。
- **资料诊断页放最后一页**：只**呈现诊断内容**（六项完整度环 + 逐项 完整/待补/缺失 状态卡），**不做在线上传功能**（用户明确"不需要在线诊断，把内容给出来就行"）。标"示例"不编造。
- **叙事主线**：痛点(光有 AI 不够) → 六项逐讲 → 为什么正好六项 → 证明(评测+现场演示) → 最后诊断"你缺啥去补"。

## 七、数据诚实（红线）
- **绝不编造评测/benchmark/业绩数字。** 没真数据就清晰标注"示意·待填真实数据"占位并主动要真数。评测图必须真实 eval 结果。
- 例子里的公司/客户是演示样例可用；不得伪造真实客户记录或第三方评价。

## 八、可选：现场真 AI 演示（放一处，别整份实时）
同源代理(避跨域) + 限额防刷(每IP+每日) + 红线硬闸 + key 只在服务端。最有说服力=「未加载 skill 的通用AI vs 加载六项资料的 AI」两栏实时对比（同模型、差别只在资料）。演示页可先放"双分身对比"图示（通用AI 空记忆 vs 悦升AI 六项点亮）再放实时框。

## 十、构建与验收流程（必须）
1. 本地**校验**：HTML 标签闭合、CSS 花括号配平、`node --check` JS 语法。
2. **逐页截图人眼核对**。playwright 可能被清掉；备用 = 直接用 chromium `chrome-headless-shell` 二进制截图（`~/Library/Caches/ms-playwright/chromium_headless_shell-*/…/chrome-headless-shell --headless --screenshot=x.png --window-size=1440,1000 --virtual-time-budget=2500 file://…`）。要看非首页/JS 生成的 view：临时把该 section 改 `class="page active"` + 注入 `<style>*{animation:none!important}</style>` 保证内容渲染出来。**及时删截图**（本机沙盒磁盘会被长会话塞满 ENOSPC，清 `tasks/*.output` 和 `*.png` 可恢复）。
3. 发布 **HK 文档中心/reports**：docker 卷 `cn-caddy-data/_data/reports/<slug>/index.html`（`cn.zenjoymedia.media/reports/<slug>/`）。部署：`scp` 到 hk-vps → `docker cp` 进 `cn-https` 容器（先 cp 一份 `.bak-时间戳`）。
4. **迭代心法**：改一版→截图→给用户看→按反馈调。用户强偏好"先看效果再决定"。

## 十一、⭐这位用户的具体偏好（务必记住，都是反复返工换来的）
- **配色**：深 navy 侧栏 + 蓝白主区 + `#2563EB`（见 §二）。别再提暗色整铺/暖纸/前沿电靛——都试过被否。
- **版式 = 头号雷区**：最恨"每页一个模子"。任何版式/图示/结构一旦套到每页都会变死板被否 → **每页当独立作品设计**，别复用模板（见 §五 🔑 元教训）。三 tab（讲解/示例/对比）可保留，但**对比别做成每页统一红蓝表格**（他不喜欢、也嫌死板）。
- **卖点**：体现"我们的资料库让 AI 答得更好"，不是秀模型；但手法换着来，别公式化（见 §五）。
- **例子**：用悦升云端自己，不用虚构第三方。字段要全、讲解↔示例对齐。
- **logo**：autopilot 官方 logo，白 logo 嵌 navy 侧栏（不要孤立徽标盒子）。nav 不放 icon。
- **诚实**：对"是不是真用了我们的 skill / 真数据 / 真主体"极较真——诚实第一，别糊弄，别编数字。
- **沟通**：讨厌"废话"，回复要精简、直接给结果。决策=给推荐+让他选；喜欢现场能演示的真家伙。
- **节奏**：会一轮轮细抠（logo/配色/字段/版式/文案），每次只认"看得见的效果"。宁可多截几次图，别猜。
