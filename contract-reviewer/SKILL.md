# Contract Reviewer（契约对抗审查官）

## 定位

Crystal Harness 的对抗不再事前写实现合同（旧 GAN 25 分钟），而是**事后对着真实契约挑刺**（15 秒）。
本 skill 是那一枪的固化版。审查对象是**技能契约**——一段声明「这一步什么时候能做、
做完了长什么样、会改变什么」的结构化文本。

核心判据（决策 28ca1f69）：**能被 CI 表达的永远不该用对抗；对抗只打语义漏洞——
"什么算干成了"这个假设对不对。** 契约是唯一的闸，契约不全 = 闸有洞 = 系统安静跑错。

## 输入

一份技能契约，字段随缺随审（**缺省本身就是最大的靶子**）：

```
技能名 / signature
用途
序列（如有）
precondition:  （可为"无"——那就是第一条漏洞的候选）
postcondition: 怎么判定干成了
side_effects:  执行会改变什么
failure_modes: 已声明的失败模式（可缺省）
```

可选附件：真实执行轨迹摘要（失败案例最有价值——对着真轨迹审比对着想象审准一个数量级）。

## 执行协议（一次调用，temperature=0）

**system prompt（逐字使用，实测验证版）：**

```
你是技能契约的对抗审查官。你的唯一职责是找出这份契约里【缺失的前置条件、
无法真正判定的后置条件、未声明的失败模式】。不要夸奖，不要复述，只输出你
找到的漏洞，按严重度排序，每条一行，格式：[严重度] 漏洞 → 后果。最多8条。
```

**user prompt：** `审查这份技能契约：\n<契约全文>`（有轨迹附件时追加 `\n真实执行记录：\n<摘要>`）

严重度词表（封闭）：`[致命]` `[高]` `[中]`。

## 输出后的两个规定动作

1. **属「判定假设」类的漏洞**（例：帖子发出去=API 200 还是截图可见？找到账号=名字出现还是
   抖音号精确匹配？）→ 按 db-update skill 写入 `decisions(category=judgment)`（登记规则
   27b57469/e035dad8），供 Invariant Gate 追踪与主理人复盘。
2. **[致命] 级漏洞未修复前，该契约不得入库/不得当闸使用**——"没探针不许固化"（决策 28ca1f69 ⑤）。

## 审查视角清单（reviewer 自查，防漏打）

- 前置：环境态（app 在前台？已登录？网络通？）、输入合法性（空值/字符集/焦点在目标控件）
- 后置：**可判定性**（首屏可见吗？要滚动吗？昵称≠账号名？）、绑定过多（一个断言绑两个事实会误报）
- 失败模式：无匹配 / 多义匹配 / 风控限流 / 缓存-坐标漂移（静默跑偏类最毒）
- 副作用：导航态、写入、外部世界可见的变化有没有全列

## 校准基准（金标，新模型上岗先跑这条）

2026-09-05 真机 A/B 实测：对 `search_account` 契约（precondition 留空的原始版）一枪应命中
≥6 条，且**必须包含**「缺失 app 在前台/搜索入口可见的前置条件」（当日 B 臂真实死因）与
「type 可能打进其他获得焦点的输入框」（当日 A 臂点飞到计算器的真实事故）。
命中率明显低于此基准 = 模型或提示词退化，禁止上岗。
数据与案卷：memory `skill-distillation-ab-verified.md`。

## 边界

- 不审代码质量（code-review-gate 的事）、不审产品提案（capability-reviewer 的事）、
  不审 PRD/DoD 格式（CI lint 的事）。
- 一份契约一枪；同一契约修复后可再审，轮数不设限，但 reviewer 真找不出实质漏洞时必须放行
  （沿用 GAN 收敛纪律，禁无限挑刺）。
