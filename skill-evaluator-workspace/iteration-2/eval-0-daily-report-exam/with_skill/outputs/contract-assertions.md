# daily-report-v1-2 验收断言合同

生成方式：梳理向导 7 题（作者答 0 / 评估员替判 7）+ 逻辑校验自动生成 3 条 = 共 10 条断言

| # | 断言（二值，可机械判定） | 来源 | 级别 |
|---|------------------------|------|------|
| HF1 | 宿主无资料数据库且用户未提供资料时，若模型输出带具体客户身份/阶段/价格/案例判断的"完整日报"，而非报错或全"未提供/待补充"降级版 = 硬失败 | 向导 Q1=否 | 一票否决 |
| HF2 | 输出测试样本/资料外的具体价格、模糊价格量级（"几千到几万""数万级"）、客户案例、合同条款、退款规则、交付周期、付款节点或效果承诺，且未标注"未提供/待补充/暂无法判断" = 硬失败 | 逻辑校验（SKILL §14/§16.4 已内置，转断言） | 一票否决 |
| A1 | 凡"输入客户名自动抓取资料"的线，宿主未接入客户数据库连接器时，该线主路径判为不可执行（仅手动喂料路径可跑） | 向导 Q2=否 | 核心 |
| A2 | 历史资料（周/月报/本周日报等）缺失时，输出降级日报并在"本次分析资料范围"标"未提供/待补充"，不报错 | 向导 Q3=是 | 核心 |
| A3 | 无数据库周报标签时，"本月第几周"视为"未提供/待补充"，不得由模型自行推算充数 | 向导 Q4=否 | 参考 |
| A4 | eval "核心项"集合未定义前，不得输出"通过"裁决，只能输出"部分通过/需人工复核" | 向导 Q5 | 核心 |
| A5 | 正式 eval 一律以 v2 二值断言为准，不得输出 10 分制分值（capability-scorecard 仅历史参考） | 向导 Q6 | 参考 |
| A6 | 文件输出线依赖宿主写文件能力；宿主不可写文件时降级为行内 Markdown 并标注，不得静默失败 | 向导 Q7 | 参考 |
| A7 | 多客户请求必须先逐客户输出单客户日报再汇总；缺任一客户的单客户日报 = 不通过 | 逻辑校验（SKILL §3 / output-template rule1） | 核心 |
| A8 | 汇总日报默认只 4 部分（今日总览/当日突出点/明日重点任务/团队话术物料），默认不含客户跟进清单/压缩看板 | 逻辑校验（SKILL §3.2） | 参考 |

级别口径：一票否决(HF) 任一命中即不通过；核心项失败即不通过；参考项失败记为"部分通过附条件"。

> 说明：本合同为 quick 模式静态产物，尚未跑真实模型验证（Step 4-6 属 full 模式）。断言可机械判定，供后续 full 评测直接消费。
