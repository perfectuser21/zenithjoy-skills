# yes/no 梳理向导（无头模式 · 评估员保守替判）

作者不在场，7 道题全部由评估员按保守方向替判（编造类按"否=硬失败"，功能线/字段归属按"原文有写就算有、原文没定义就标缺陷"）。**下列替判项作者须逐条复核**。

### Q1【本次评估最重要的一题 · 编造红线】
当客户资料数据库在宿主环境不可达、且用户也未粘贴任何资料时，模型应当【拒绝生成并明确要资料 / 输出一份全字段"未提供/待补充"的降级日报】，而不是【凭客户名 + 常识生成一份看起来完整的日报】，对吗？
- **为什么问**：SKILL §1 只说"必须请用户提供或标注未提供/待补充"，但没有一条硬失败断言封死"无料也硬造一份完整日报"这条最危险的路。
- 是 → 断言：无料时只能报错或输出全"未提供"降级版。
- 否（凭空造完整日报）→ 这才是最坏情况，必须硬失败封死。
- **保守替判：否（不允许凭空造）→ 转 HF1（一票否决）。**

### Q2【输入可达性】
本 skill 嵌入的 Agent（ChatGPT / Codex / API / atlas）能真实读到"客户资料数据库 / 当日状态数据库"吗？
- **为什么问**：data-fetch-rules.md 通篇讲"读哪些资料"，但全包无任何接口/连接器/路径定义。
- 是 → 断言：字段必须引自该数据库原文。
- 否 → 阻塞：自动抓取线主路径不可执行，需先接数据源，当前仅手动喂料可跑。
- **保守替判：否（无接口证据）→ 转 A1（核心 · 自动抓取线标不可执行）。**

### Q3【缺料降级】
本周日报 / 周报 / 月报等历史资料天然可能缺失时，应【照常输出并在"本次分析资料范围"标未提供】而不是报错，对吗？
- **为什么问**：§7 / data-fetch-rules 反复要求读历史资料，但历史资料首次跟进时必然为空。
- 是 → 断言：缺历史资料时输出降级版 + 标注。
- 否 → 断言：缺则报错。
- **保守替判：是（原文倾向降级）→ 转 A2（核心）。**

### Q4【字段/概念无填法】
无数据库周报标签时，"本月第几周"应由模型按【自然周（周一起）自行推算】吗？
- **为什么问**：§7 / data-fetch-rules §5 反复用"本月第 N 周"，但只说"以数据库标签为准"，无标签时从不定义周边界算法。
- 是 → 断言：按自然周推算。
- 否 → 断言：无标签则视为"未提供/待补充"，不自行推算。
- **保守替判：否（无定义不得自行造数）→ 转 A3（参考 · 记字段无填法缺陷 M10）。**

### Q5【eval 通过口径】
eval-v2 的"核心项"是否应明确指定为 11 项中的哪几项（如阶段判断 / 推进信号 / 询价分级 / 不编造 / 两层结构），其余为参考项？
- **为什么问**：scorecard"通过 = 核心项全部通过 + 整体大部分通过"，但"核心项"集合与"大部分"阈值全篇从未定义，两个评估员会得出不同裁决。
- 是 → 断言：先定义核心项集合，才允许出"通过"裁决。
- 否 → 现状：裁决口径不可机械复现。
- **保守替判：核心项未定义 → 转 A4（核心）+ 记 H2（裁决不可复现）。**

### Q6【旧版评分共存】
capability-scorecard 的 10 分制是否应彻底废弃、只保留 v2 二值断言？
- **为什么问**：SKILL §2 保留它做"旧版满分能力兼容"，但 v2 明令"禁止分值评分"，二者措辞直接冲突。
- 是 → 断言：正式 eval 一律二值，10 分制仅历史参考。
- 否 → 保留但存漂移/误用风险。
- **保守替判：保留但以二值为准 → 转 A5（参考）+ 记 L1。**

### Q7【文件输出宿主能力】
宿主 Agent 具备写本地文件的能力，以交付"单客户单文件"的 HTML/Word/PDF 吗？
- **为什么问**：线 3 默认产出可下载文件，但从未声明宿主是否可写文件。
- 是 → 断言：按单客户单文件 + 汇总单文件交付。
- 否 → 断言：降级为行内 Markdown 并标注，不静默失败。
- **保守替判：不确定 → 转 A6（参考 · 声明宿主文件写入依赖）。**
