# 逻辑校验缺陷清单（8 类全文件清扫 · 单列纪律）

统计：**2 H · 11 M · 3 L = 16 条**。每条独立编号，不合并同类项。

## H 级（会导致某条功能线输出错误或不可执行）

### H1 · 输入无来源：全包无任何客户资料数据源接口定义
- **描述**：6 条日报线的公共前提是"按客户名从数据库自动抓取资料"（SKILL §1/§5），但整包无任何数据库/连接器/API 的接口、路径、协议或字段 schema 定义；data-fetch-rules.md 通篇只讲"读哪些资料"，从不讲"从哪个接口读"。自动抓取主路径在宿主内不可执行。
- **位置**：SKILL.md §1、§5.2；data-fetch-rules.md 全篇（尤其"二、必须纳入分析的资料"）。
- **缓解**：skill 定义了降级路径（DB 不可达→请用户提供资料包/标注"未提供"），故手动喂料路径可跑，非彻底死路。
- **修复**：声明具体数据源接口（连接器名/路径/字段 schema），或把定位显式改写为"用户提供资料包"模式，删除"自动抓取"承诺。

### H2 · 标准模糊：eval 通过口径"核心项"从未定义，裁决不可复现
- **描述**：eval-v2-scorecard §五 / eval-v2-sop §十一 定义"通过 = 核心项全部通过 + 整体大部分评测项通过"，但 11 项中哪些是"核心项"、"大部分"的阈值是多少，全篇从未定义。两个评估员对同一输出会得出不同的"通过/部分通过"裁决 → 线 5（严格 Eval）的输出（裁决）不可机械复现。
- **位置**：eval-v2-scorecard.md §五/§七；eval-v2-sop.md §十一。
- **缓解**：单项二值判定（通过/不通过/需复核）本身可复现，仅 roll-up 裁决模糊。
- **修复**：明确指定核心项集合（建议：A1-A4 阶段判断 / 推进信号 / 询价分级 / 不编造 / 两层结构 5 项为核心），并给"大部分"数值阈值。

- **修复**：定义无标签时的周边界算法，或明确无标签则标"未提供/待补充"（对应断言 A3）。

### M11 · 只有禁令缺"资料缺失标准句式库"

- **修复**：新增 references/missing-data-phrasebook.md，把缺价格/缺案例/缺合同/缺周期等场景的合规话术成库。

- **修复**：文件顶部加更强弃用警示，或彻底移除仅留 CHANGELOG 记载。

- **修复**：补触发词边界或收紧隐式触发。
