# 功能地图

被测 skill：daily-report-v1-2（zip 名「日报skill-v1.2-7.7」）· 来源 Claude 格式（SKILL.md + frontmatter，另含 ChatGPT/Codex/API 兼容的 agents/openai.yaml）· 归属 ZenithJoy › Line 02 客户智能获客路径 › 客户日报（ability）（用户确认）

评估模式：quick（功能地图 + 梳理向导 + 逻辑校验，零 API 成本）

共 7 条功能线：

| # | 功能线 | 触发/入口 | 输入依赖 | 输出 | 依赖健康度 |
|---|--------|----------|---------|------|-----------|
| L1 | 单客户当日日报 | 报 1 个客户名 | 客户数据库 · 当日状态库 · 当天聊天 · 本周日报/本月周报/客户月报(可缺) · 客户档案 · 企业信息 · 产品信息 | 单份日报（11 字段表） | ⚠ 宿主连接器未定义，降级已定义 |
| L2 | 多客户两层日报 | 报多个客户名 | 同 L1，逐客独立读取 | 逐客单日报 + 所有客户当日总结日报(4 部分) | ⚠ 同上 |
| L3 | 仅汇总日报 | 用户明确「只要汇总/只要总表/不要逐客」 | 同 L2 | 仅所有客户总结日报 | ⚠ 同上 |
| L4 | 详细逐客户分析 | 用户要求「详细版/完整分析/逐客展开」 | 同 L1 | 7 段详细模板 | ⚠ 同上 |
| L5 | 可下载文件输出 | 用户要求导出 HTML/Word/PDF/Markdown | 同 L1/L2 + 宿主文件写能力 | 单客户单文件 + 汇总单文件(+可选 index) | ⚠ 依赖宿主文件写能力 |
| L6 | 快速冒烟 Eval | 「跑快速冒烟测试」 | 内置 eval-simulation.md 6 固定样例 + 期望核心判断表 | 冒烟结论（无 baseline，标注非正式验收） | 🔴 内置钱总样例含诱导编造矛盾(H1) |
| L7 | 正式 Eval / Baseline 对比 | 「验收/回归/对比」+ 明确测试类型(12/30/50 样本) | golden-answer 模板 · 二值断言表 · Baseline0/1 需宿主独立模型实例 | Eval V2 报告(二值断言+典型客户证明) | 🔴 golden 示例自相矛盾(H2)；baseline 需宿主多实例，skill 诚实标注待补跑 |

说明：
- L3「仅汇总」按 SKILL §3.3 是独立触发（跳过逐客只出总结），输出物形态与 L2 不同，故单列。
- frontmatter 顺嘴提到的「销售复盘日报」无独立模板，实为 L1/L2 日报的用途别名（见向导 Q7），不单独立线。
- 「变更记录」是 L1/L2 日报内的条件字段（有历史材料时出现），非独立触发线，未单列。
- 周报/月报仅作为**输入**被读取（§7），skill 不生成周报/月报，故无对应功能线。

依赖类型盘点：
- 数据库/API：客户数据库、当日状态库 —— **skill 全包无任何接口/schema/连接器定义**（详见缺陷 H3），主路径靠宿主提供。
- 文档/知识文件：output-template / data-fetch-rules / eval-v2-* / capability-scorecard 等 11 个 references，均在包内（活性见全文件清扫）。
- 实时上下文：当天聊天记录 —— 默认由数据库读取，宿主不可达时降级为用户贴资料。
- 凭据：未涉及（skill 不直接调外部凭据，交由宿主连接器）。
- 宿主能力：文件读写（L5 导出）、独立模型实例（L7 baseline）、数据库连接器（L1-L5）。
- 历史产物：昨日日报/本周日报/本月周报/客户月报 —— 缺失时降级已定义（标注「未提供/待补充/本周暂无历史日报」）。

核心结论：**7 条线共用同一套「按客户名读库 → 分析 → 日报」骨架，日报分析规则（A1-A4 阶段、四感模型、推进信号、询价分级、风险识别、缺料降级）设计扎实且降级路径完整；主要风险集中在（1）Eval 线的内置样例/golden 自身诱导编造（H1/H2），（2）全部日报线依赖的数据库连接器在包内零定义（H3，有降级兜底）。**
