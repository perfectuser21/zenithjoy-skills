# 逻辑校验缺陷清单 —— daily-report-v1-2

方法：对全包 13 个文件过 8 类逻辑校验，含第 1 类「样例也是条款」独立扫描、第 8 类全文件逐文件清扫。**单列纪律：每条独立缺陷单独编号，不合并同类项。**

统计：**3 H · 11 M · 4 L，共 18 条。**

---

## H 级（导致某条功能线输出错误或不可执行）

**H1 · 第1类样例矛盾 · 诱导编造**
- 描述：快速冒烟 Eval（L6）内置「期望核心判断」表中，钱总（调研型询价、样本未提供产品价格）的「下一步动作方向」写**无条件的「给价格区间」**，与 §11.2 / §14「未提供产品价格时一律写『报价区间待产品信息提供后输出』，不得给任何数字或量级」直接冲突。样例即条款，模型会优先模仿样例 → 冒烟自测会把编造判为通过，编造红线自我失效。
- 位置：references/eval-simulation.md:83（对照 SKILL.md:176 §11.2、SKILL.md:221 §14）
- 修复：钱总期望改为「报价区间待产品信息提供后输出 + 适用条件 + 二次沟通节点」，去掉「给价格区间」。

**H2 · 第1类样例矛盾 + 内部矛盾 · 诱导编造**
- 描述：正式 Eval（L7）的钱总示例 Golden Answer 内部自相矛盾：第 7 条「下一步动作方向：给价格区间」与同一文件第 9/10 条「不得编造具体价格、未提供只能写『待补充』」冲突。Golden 是评测的黄金标准，标准答案自身诱导编造 → 正式 Eval 会奖励编造输出。
- 位置：references/eval-v2-golden-answer-template.md:221（对照同文件:229、:234）
- 修复：第 7 条改为「报价区间待产品信息提供后输出」，与第 10 条事实边界对齐。

**H3 · 第2类输入无来源（主路径依赖宿主，有降级兜底）**
- 描述：全部 5 条日报线（L1-L5）默认场景「报客户名 → 自动读客户数据库/当日状态库/企业信息/产品信息」，但 skill 全包**无任何数据接口/schema/连接器路径/查询示例定义**。未挂载连接器的宿主里主路径不可执行。**注：skill 已定义降级（不可达时标注「未提供/待补充」或请用户贴资料），故非致命——降级模式（用户贴资料）可跑，主路径可执行性完全取决于宿主是否提供连接器。**
- 位置：SKILL.md:10-12 §1、references/data-fetch-rules.md:16-28 二
- 修复：明确声明「本 skill 不含数据接口，主路径依赖宿主提供 X 连接器；宿主未提供时以降级模式运行」，把宿主依赖写成显式前置条件而非默认能力。

## M 级（降低跨模型稳定性或可维护性）

**M3 · 第8类第4问名词无定义**

**M4 · 第5类标准模糊**
