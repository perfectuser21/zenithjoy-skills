# 怎么查清楚"糊糊大老婆"在微信会话列表里的真实显示名字

## 问题本质

你的脚本用**子串匹配**遍历微信主窗口的 `ListItem` 控件来找目标联系人。匹配失败（`[主动发送] 找不到 糊糊大老婆`）只有两种可能：

1. **你给的 `target`（"糊糊大老婆"）根本不是微信里那一行的显示文本**——这是最常见的原因。微信会话列表里显示的是**备注名 / 昵称 / 群名**，"糊糊大老婆"是你脑子里的称呼，UIA 读到的 `Name` 属性是另一串字。
2. 那个会话**当前不在列表可见范围里**（被滚动隐藏了、或根本没出现在会话列表中）——UIA 默认只能枚举到已渲染的 ListItem。

所以核心动作是：**把脚本现在实际能读到的所有 ListItem 的真实文本（Name）打印出来**，用眼睛找到她那一行到底叫什么。

---

## 方法一（首选）：让脚本自己 dump 会话列表的真实 Name

你的脚本已经在遍历 ListItem，只要在"找不到"的那段逻辑里，把遍历到的每个 item 的 `Name` 全部打出来即可。这是最可靠的，因为它读的就是脚本运行时看到的同一份控件树（同一个 uiautomation 版本、同一个窗口实例）。

在主动发送找联系人的循环里加一段诊断输出，例如（uiautomation 库，Python）：

```python
import uiautomation as auto

# 拿到微信主窗口（按你脚本现有方式拿，下面是通用写法）
wechat = auto.WindowControl(searchDepth=1, ClassName='WeChatMainWndForPC')

# 会话列表通常是一个 List 控件，里面是若干 ListItem
# 先把窗口里所有 List 的所有 ListItem 的 Name 全打出来
for lst in wechat.GetChildren():  # 实际要按你脚本里定位会话列表的方式来
    pass

# 更直接：递归/遍历你脚本里已经拿到的那个会话 ListControl
session_list = ...  # 你脚本里已有的那个会话列表控件
for i, item in enumerate(session_list.GetChildren()):
    name = item.Name
    print(f"[dump] index={i} Name={name!r} ControlType={item.ControlTypeName}")
```

关键点：
- **用 `repr()`（`{name!r}` 或 `print(repr(name))`）打印**，这样能看出有没有**前后空格、不可见字符、emoji、零宽字符**。很多"子串匹配失败"是因为名字里带了 emoji 或空格，肉眼看着一样、字节不一样。
- 微信会话列表的 ListItem，它的 `Name` 往往**不是单纯的联系人名**，而是类似 `"糊糊  [置顶]  下午 3:21  消息预览..."` 这种把名字+时间+最后一条消息拼在一起的长字符串。这正好解释了为什么子串匹配会失败/错配——你得看清楚真实结构，再决定截取哪一段做匹配。

把这段 dump 跑一次，日志里就能看到她那一行真实的 `Name` 长什么样，直接拿那个字（或其中稳定的子串）当 `target` 重发即可。

---

## 方法二：用 inspect.exe / Accessibility Insights 直接看控件树

不想改脚本的话，用现成的 UIA 查看工具，把鼠标悬停到微信会话列表里她那一行，直接读 `Name` 属性：

- **Accessibility Insights for Windows**（微软官方，免费，推荐，比老 inspect 好用）：打开后开启 Live Inspect，鼠标移到那一行会话上，右侧面板看 `Name` 字段。
- **inspect.exe**（Windows SDK 自带，路径类似 `C:\Program Files (x86)\Windows Kits\10\bin\<ver>\x64\inspect.exe`）：选 UI Automation 模式，悬停同理。
- **uiautomation 库自带的 `automation.py -t 3`**：在装了 `uiautomation` 的环境里运行 `python -m uiautomation -t 3`，3 秒后它会把当前鼠标下的控件树 dump 出来——把鼠标停在她那行会话上即可。

这些工具读到的 `Name` 就是 UIA 看到的、你脚本匹配用的同一个值。

> 注意：用第三方工具看到的值，和脚本运行时看到的值**理论上应一致，但不绝对**——微信不同版本、不同窗口状态控件树可能不同。**最权威的还是方法一（脚本自己 dump）**。

---

## 方法三：直接从微信 UI 确认备注名（辅助验证）

在微信里点开和她的聊天 → 点右上角 `···` → 看资料页的"备注"和"昵称"。会话列表里那一行显示的优先级一般是：**备注名 > 昵称**。

- 如果你设了备注，列表显示的就是**备注名**——你脚本的 `target` 必须用这个备注名（或它的子串），而不是"糊糊大老婆"。
- 如果没设备注，显示的是她的微信**昵称**（可能带 emoji、特殊符号）。

这一步能帮你"人肉确认"，但**最终一定要回到 UIA 读到的字节**（方法一），因为昵称里的 emoji / 空格 / 特殊字符在 UI 上看不全。

---

## 排查清单（按顺序做）

1. **先确认会话在列表里可见**：在微信主窗口里能直接看到和她的会话吗？如果被滚动到下面看不见，UIA 可能枚举不到——先点一下让它出现在列表顶部，或在脚本里加滚动/搜索逻辑。
2. **跑方法一的 dump**，用 `repr()` 打印所有 ListItem 的 `Name`，找到她那一行的真实文本。
3. **观察真实 Name 的结构**：是纯名字，还是"名字+时间+消息预览"拼接串？据此调整匹配（比如只取分隔前的第一段，或对整串做 `in` 子串包含）。
4. **检查隐藏字符**：repr 里有没有 emoji、前后空格、零宽字符。有的话，要么把 `target` 写成完全一致，要么改成"去空格 + 包含匹配"。
5. **拿到真实显示名后**，把命令文件里的 `target` 改成那个真实名字（或一段稳定子串），重新投放命令文件重发。

---

## 给脚本的长期改进建议

光这次查清楚还不够，建议顺手加固：

- **匹配失败时自动 dump 候选列表到日志**：把 `[主动发送] 找不到 X` 改成同时打印"当前会话列表里实际有这些：[...]"，下次再遇到一眼就知道该填什么，不用再单独排查。
- **匹配用归一化子串**：`target.strip()` 后做 `in item.Name`（忽略空格、忽略拼接的时间/预览部分），并对多个候选给出提示（避免"糊糊"同时匹配到多个会话发错人）。
- **多命中要报警而不是随便选第一个**：如果 `target` 子串命中了不止一行，应该记日志让人确认，避免发错对象。
- **找不到时尝试用微信搜索框定位**：在会话列表枚举不到时，可以走微信顶部搜索框输入名字→回车打开会话，再在当前聊天窗口发送（你的 `reply_in_chat` 路径），这样不依赖会话列表是否已渲染。

---

## 一句话结论

"糊糊大老婆"是你的私人称呼，不是微信里那一行的真实文本。**最快的办法是在脚本"找不到"分支里用 `print(repr(item.Name))` 把会话列表所有 ListItem 的真实 Name 打出来**，找到她那一行实际显示的备注名/昵称（注意 emoji、空格、以及"名字+时间+消息预览"的拼接结构），然后把命令文件的 `target` 改成那个真实字符串或其稳定子串重发即可。
