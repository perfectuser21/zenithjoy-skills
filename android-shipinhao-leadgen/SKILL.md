# 安卓视频号关键词获客（com.tencent.mm 内嵌 Finder）

> **熟化阶段：EXPLORE**（第1次，0919 首次蹚通，同日三轮纠偏）· 连续零新坑 0/3
> **结论几经修正，以本版为准**：第一轮判定"私信路径完全不通"是错的——只测了"纯路人甲评论者"
> 和"一个碰巧开店的认证号"两个样本就下了结论。第二/三轮补测"普通人但自己发过内容"
> "认证但没开店的企业号"两类样本后发现：**私信其实是主流，不是例外**。详见下方判定树。

坐标为 1200x2664（小龙虾）实测参考，前提：微信已登录、视频号已开通。

## 潜在客户头像 → 判定树（本skill核心）

点评论者头像后，走向分两种：**直接跳全屏主页**，或**先弹半屏信息卡**（卡片上若显示"他的视频号"
缩略图入口，点进去同样能到全屏主页——这是同一个终点的两条导航路径，不是两种结果）。

```
点评论者头像
├─ 该用户从未发布过视频号内容
│    → 半屏信息卡：仅昵称/籍贯/简介，无任何按钮，无"他的视频号"入口
│    → ❌ 死路，只能建档标记"待其他渠道核实联系方式"
│
└─ 该用户自己也发布过视频号内容（哪怕只有1-2条，不要求认证）
     → 全屏 FinderUserProfileUI：昵称/籍贯/性别/简介/内容数 + 按钮区
     ├─ 无「商品橱窗」（绝大多数：普通个人号 / 服务型认证企业号都算）
     │    → 按钮 = 关注 + 【私信】
     │    → ✅ 点"私信"进 ChattingUI（普通聊天窗口，非客服壳）
     │       平台规则原文："对方回复前，仅可发1条消息"（同快手/小红书按人头计数模型）
     │
     └─ 有「商品橱窗」（开通了微信小店带货，标题栏会显示"微信小店带货"）
          → 按钮 = 关注 + 【客服】
          → 🟡 点"客服"进 OpenImKefuServiceChattingUI
             底部**有正常文字输入框**，能发消息，非只读——挂了"咨询订单/咨询商品/
             平台客服/评价服务"4个预设快捷标签，暗示对方期待订单类咨询语境，
             发送非订单相关内容不会被拦截，但话术要包装成"咨询"更不违和
```

**样本实证（0919，"职场干货"关键词批次）**：
- "高山流客"（纯评论路人，无自己内容）→ 半屏卡片无按钮 → 死路
- "幸福happy一家子"（上海，普通个人，2条原创，无认证无开店）→ 全屏主页 → **关注+私信** → 私信开1条
- "铠洛博Comglobal"（认证蓝V企业号，HR咨询服务，27条内容，无开店）→ 全屏主页 → **关注+私信**
- "辰涛学习坊"（认证生活博主，574条内容，**有商品橱窗**）→ 全屏主页 → **关注+客服**（"微信小店带货"）

四个样本三私信一客服——**私信是主流，客服才是少数（仅限真正带货的号）**，跟"认证与否"无关，
只跟"发没发过内容"+"开没开店"这两个二元条件挂钩。

## 评论者主页信息字段（供 Lead 建档）

| 字段 | 来源 | 备注 |
|---|---|---|
| 昵称/头像/籍贯（省份） | 评论条直接可见 | 最低成本抓取，不用点进主页 |
| 性别/简介/内容数 | 全屏主页直接可见 | 需点开主页 |
| **视频号ID**（如`sphmKSN6NfZ5egp`）/ 账号实名 / IP归属地 / 认证信息 | 主页右上"•••"→"更多信息" | 唯一标识建议用视频号ID去重，不用昵称（可能重名）。**⚠️ 视频号ID 不能拿去微信"添加朋友"搜索加好友，返回"该用户不存在"——它跟微信号(wxid)是两套不互通命名空间，只有档案价值，没有二次触达价值，触达只能走上面判定树的私信/客服按钮，不能靠这个ID换个小号另起炉灶联系** |

「•••」菜单里还有个「推荐给朋友」选项，**不是联系对方**——点了会跳转微信原生"选择聊天"，
把这张名片转发给**你自己**的联系人/群，可以当"建档暂存点"用（见下）。

## 建档/暂存机制（0919 验证，主理人提议）

关键词获客的"发现→判定→触达"三步不需要在同一次导航里一次走完。可以先把候选名片**转发到
一个固定的联系人或群**（用「•••」→「推荐给朋友」，或视频播放页自带的"转发"图标→"转发给朋友"，
两个入口效果一样），当"暂存筐"用，之后再批量回来处理：

- 转发进去的是**活卡片**（视频封面+视频内嵌字幕文字+来源账号名，点开能直接播放原视频），不是
  死截图，可以再点进去走上面的判定树
- 「选择聊天」的搜索框搜的是**全通讯录联系人**（不只是最近聊天），只有"文件传输助手"这种系统
  特殊号被排除在外
- 用固定接收点的好处：不管候选人是从哪条视频/哪个搜索词发现的，"转发进固定筐"这个操作序列
  永远一样，比对每个候选直接originate处理更适合RPA固化（动作原语稳定，不用应对散落各处的
  UI布局差异）
- 卡片表面能看到：封面缩略图+文案字幕+来源账号名；**看不到**视频号ID/实名/IP归属地，深层字段
  仍需点开卡片→点头像→点"更多信息"才能拿

## 触达频控（沿用抖音获客同款铁律，规则本身不同型）

- 私信侧：官方明文"对方回复前仅可发1条"，按人头计数，不是按时间窗口节流——**不可套用抖音
  "20条/小时"的模型**，一个对象只有一次机会，用不好就浪费
- 客服侧：未实测频控上限（本skill全程未真发，见下）
- 真实发送前必须先用测试小号小批量试跑，确认不触发风控/限流，**不能直接用业务账号批量发**

## 已验证 vs 未验证

✅ 已验证（0919 三轮真机实测）：
- 判定树三条分支（死路/私信/客服）均有真实样本佐证
- 私信窗口的频控规则文案（对方回复前限1条）
- 客服窗口确认有可用输入框，非只读
- 视频号ID 不能用于"添加朋友"加好友（该用户不存在）
- "推荐给朋友"/"转发给朋友"是分享给自己联系人，不是联系对方；落地卡片是活的可再点开

❌ 未验证，下次探索/上线前必须补：
- **本skill全程未执行任何一次真实发送**（私信/客服消息均未点发送），实际发送后的成功信号、
  对方视角看到什么、多批次后账号安全表现，全部未知
- 私信"对方回复前限1条"是否有更高层的账号级别总量限制（今天能对多少个不同新对象发起私信）
- 客服消息发送非订单相关内容，是否会被平台/商家自动客服拦截或标记异常
- 评论区长列表下滑加载更多的操作细节
- "判定树"里"有无视频号内容"这个分支的命中率——目标画像人群里到底有多大比例自己也发内容，
  决定了这条路能覆盖多少人群，需要实跑一批统计
