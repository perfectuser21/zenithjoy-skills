# 安卓微博发布（com.sina.weibo）

## 视频分支

2026-11-27 在西安 M4 小彩复验微博 16.11.3。该版本创作加号从「相册」进入选材，发布页有必填内容声明。旧版若有独立「视频」菜单，按当次实屏进入，底座的设备锁、素材和单次提交规则仍适用。事例 `rpa-weibo-color-51e63312d929` 中，已确认账号的微博计数从 8 到 9，最新一条为同一段 6 秒视频，可见范围为「仅自己可见」。

| 步骤 | 真机动作与完成判据 |
|---|---|
| 1 | 取得设备双锁。微博「我」页核对当前绑定账号和微博基线计数。按底座下发当单视频，保留源摘要、时长及索引回执。 |
| 2 | 回首页打开右上加号，选「相册」。等相册展开稳定并实际出现「全部」「图片」「视频」后选「视频」。切换前用现行控件树或当前完整实屏定位。 |
| 3 | 确认目标缩略图和时长唯一，打开预览核对源素材。若目标与旧素材多义，停在选材，改用本轮可唯一辨认的已批准素材。确认为目标后点底部「下一步」，进入视频编辑页。 |
| 4 | 在视频编辑页核对同一素材，保留任务自带音频，按底座处理额外配乐。点右上「下一步」进入「发微博」。读回账号和视频卡。 |
| 5 | 按批准素材选择投稿类型。若页面有「内容声明（必填）」，打开面板并等所有选项和「确定」出现。按素材事实选择，确认后在发布页读回。可选文案用受控 `text-input` 并精确读回。当单指定文案写入或读回失败时，保留回执并停在提交前。 |
| 6 | 打开分享范围，选「仅自己可见」，返回发布页再次确认锁标和文字。确认同一账号、素材、声明和可见范围后，使用持锁控制器记一次 `--outward publish`，只点一次「发送」。 |
| 7 | 若首页显示「微博发送中」，等待并只读核对进度。回同账号「我」页核对计数 +1，再打开「微博」列表检查首条的本次时间、视频封面、时长和「仅自己可见」。保存原回执，回安全桌面并读回两把锁都为空。 |

相册从半屏展开成全屏时，「视频」标签的位置会移动。点进意外素材预览时立即返回，并重新确认完整相册及目标素材。内容声明也会随面板展开移动，选择后先核对勾选项。本轮源素材无声，独立复核同一视频私密提交一次。带规定文案的任务仍需文案本身精确读回。

## 图文分支：安卓单张图片（含长图）

> **熟化：蒸馏**（首次沉淀 · 来源 run codex-1010-weibo-image-2150 · 更新 1010）
> 判例计数：图片编辑层 ×1；桌面坐标误开 ×1；个人主页设置误认 ×1；相册坐标混用 ×1；首次编辑引导 ×1；证据名触发 outward 拒绝 ×1；back/swipe 参数不兼容 ×1；原图引导 ×1；原输入法恢复 ×1。
> 本分支由 Codex gpt-6.1-sol 在安卓 App 执行，独立核验任务 e0a20067-bfa9-4d9a-a737-ed814a0ba932 判定 pass。视频分支保留原有实测记录；本次新增能力限单张图文，素材可为长图，不代表原生文章或多图已验证。

### 前置与设备
- 公共底座引用 android-publish，不复制设备锁、冷却、素材下发规则。开工先登记 Brain 任务，取得 controller 与 Brain 的同设备双层锁；现有账号已登录，不登录或换号。
- 使用批准的手机 controller 通道，根据当前原图或控件树选控件。视频与图文都遵循底座当前通道和输入保护。
- 内容从 Notion 真身取，单张素材为自己创建的 JPG；源路径、尺寸、hash 登记并与图库预览核对，不能选私人相册旧图。来源运行验证的是一张 1080×3240 长图。
- 中文用正常 text-input：先真实聚焦，受 guard 拒绝即保留证据停止，不直接广播绕过；原输入法先留证据，输入后恢复原值。来源原值即 AdbIME，恢复相同值不是新增残留。
- 新运行每步证据 ID 包含 run_id、步号和时间；截图与 XML 均持久保存，来源原始证据不改名、不重构。

### 图文成功判定
1. 正确账号计数仅加1，最新作品为任务单张图片、精确文案、匹配新时间且仅自己可见。
2. 同run原始outward账本仅一次publish attempt/result，allow_repeat=false，无重复投稿。
3. 本run有launcher原回读及两层锁精确owner释放原请求响应，结束后锁free。
证据：来源 09-account、30-count、39-new-card、40-large-image、outward-ledger-original.jsonl、cleanup-original.txt、lock-release-original.json、brain-release-original-rows.jsonl；由 run-verify 独立判定，不由执行者自报。

### 图文契约
- 前置条件：Brain任务已登记认领；双锁有效；安卓微博现有指定账号已登录、网络可用；内容来自Notion真身；自制单张JPG可核对路径/hash/尺寸；底座冷却满足；原IME与基线留证据。
- 后置条件：满足上述三条成功判定；不以发送提示、后台上传或仍在审核代替作品回读。缺项为unknown，失败或拦截为blocked。
- 副作用：账号新增一条仅自己可见单张图文；controller记录一次outward发布；Brain回写事实/证据/actor/handoff。原账号、私人图库、设备镜子与原输入法不修改。
- 失败模式：素材未索引/无匹配/多义匹配；控件漂移；登录、绑定或风控；输入guard拒绝；首次引导挡住转页；提交超时/上传未完成/重复账本；作品或私密回读缺失；锁或桌面原回执缺失。对外失败不重试，提交未知先只读核验。

### 图文首次坑
- 图片分支存在“图片编辑层→正文页”独立转页，旧视频步骤不能代替（×1）。
- 桌面坐标混用曾误开唯品会欢迎页，未同意协议或登录；以后必须看当前图标语义，不复用换算坐标（×1）。
- 个人主页顶部设置不是发布加号；发布菜单在首页（×1）。
- 相册坐标混用曾只关闭菜单；用当前控件树“相册”边界中心，不把关闭菜单当成功进入（×1）。
- 首次编辑引导使首次“下一步”仅关闭引导；确认原图/XML仍为编辑页再做转页动作（×1）。
- evidence ID中publish-menu曾被controller拒绝且tapped=no；普通菜单用普通ID，真正发布仍必须显式outward审计（×1）。
- 当前back/swipe不接收global lock-owner；拒绝未执行后只能在已持锁状态用支持的正式controller语法，不转裸ADB（×1）。
- 原图首次有左右滑动引导；不能拿遮挡或已关闭查看层的图冒充完整原图，重新语义确认（×1）。
- 原IME即AdbIME，正常输入后恢复相同原值，不能把原状态算本次失败（×1）。
