# 摸边界 skill-boundary

目标：**不是查有没有问题，而是把边界摸出来**——每个边界都要有结论，摸到的东西写回去，最后交出一份稳定成功的整流程 skill vN，给第③步验证去连续跑。

Brain 地址：`BRAIN=${BRAIN_URL:-http://100.79.41.61:5221}`。探索期**不计数**（决策 5826ddd7）。

## 你拿到的材料

| 材料 | 来源 |
|---|---|
| 整流程 skill 当前版 | 第 0 轮：试跑交付物的 `flow_skill_v1`；之后每轮：上一轮交付物的 `flow_skill` |
| 边界清单 | 第 0 轮由你列；之后每轮：上一轮交付物的 `boundaries` |
| 故障处置表 | 按整流程 skill「依赖对象」取：`curl -s "$BRAIN/api/brain/enablers?keys=<对象1>,<对象2>"` 的 `failure_semantics`；取不到的用工位 AGENTS.md「故障处置表」通用层初始值 |
| 设备 | 任务【执行参数】给定的**测试手机、测试账号**；要碰手机却没给 → blocked |

每一轮是一张任务、一段新会话，只用上一轮交付物和本轮任务给的材料。

## 第 0 轮：列清单，不跑流程

### 1. 逐格列边界

按格子逐格过：**流程的每一步 × 这一步碰到的每个依赖对象 × 三种出错方式**。

| 依赖对象 | 等的东西没来 | 来了但不对 | 被打断 |
|---|---|---|---|
| 页面、控件 | 没加载出来 | 页面不对、弹窗挡住 | App 闪退、回到桌面 |
| 网络 | 慢、转圈 | 返回错误 | 断网 |
| 手机、adb | 没响应 | 输入法不对 | 掉线、锁屏 |
| 账号 | — | 账号不对、掉登录 | 风控、验证码 |
| 目标内容 | 搜不到 | 已删除、私密 | — |
| 外部服务（模型、飞书、Brain） | 超时 | 限流、字段错 | 服务挂了 |
| 自己的数据 | — | 已经做过 | — |

每个格子要么列出边界项，要么写「本步不涉及」。每个边界项写四样：

| 字段 | 写什么 |
|---|---|
| 类别 | 输入类 / 故障类 / 平台惩罚类 |
| 怎么造 | 输入类写用什么输入；故障类写造法（见下表）；平台惩罚类写「不造，自然遇到再记」 |
| 在哪一步造 | 故障类造在**最容易出事的那一步**（例：断网放在搜索结果加载时） |
| 预期 | 动手前写好：应该命中处置表哪一行（四分类 + 参数），或流程该怎样结束 |

### 2. 证明造法能生效、能恢复

规矩：**一次只执行一条控制器命令，禁止裸 adb**。每种要用的造法先在测试手机上单独试一次（不跑流程）：造出来 → 截图看到效果 → 恢复 → 截图看到恢复。**没亲眼见过它生效的造法不算数**，对应边界记「造法未证实」，不进入轮次。

| 故障 | 造法（抖音控制器） | 恢复 | 状态 |
|---|---|---|---|
| App 闪退 | `close-app`（强制停止并回桌面） | 流程自身重启 App，或 `open-app` | 可用 |
| 被打断、回到桌面 | `return-safe-desktop` | 流程自身回到 App | 可用 |
| 被别的 App 抢前台 | 控制器 `open-app` 只能开抖音，造不了 | — | 未就绪 |
| 断网、网络慢 | 控制器暂无命令 | — | 未就绪 |
| 锁屏 | 控制器暂无命令（只有 `wake` / `unlock`） | — | 未就绪 |
| 输入法被切走 | 控制器暂无命令 | — | 未就绪 |
| 手机掉线 | 控制器暂无命令，且有断开控制通道风险 | — | 未就绪 |
| 输入类（搜不到、已删除、冷门、热门、特殊字符） | 用输入本身造：一串确定无结果的乱码、一条已知已删除的链接 | — | 可用 |

其他平台控制器以它自己的 `--help` 为准，同样只用它已有的命令。状态为「未就绪」的边界：结论记 `not_probed`，写明「控制器暂无造法」，**不卡住出口**，在交付物 `blocked_probes` 里列出（控制器补命令后再补摸）。

### 3. 排轮次

| 类别 | 一轮放几项 |
|---|---|
| 输入类 | 最多混 3 项 |
| 故障类 | 一轮只造一种 |
| 平台惩罚类 | 不单独排；全程遇到风控、验证码、限号**立即停**，记下来，本轮结束 |

轮数 = 输入类项数 ÷ 3 向上取整 ＋ 可用故障类项数 ＋ 稳定轮 3 轮。**总上限 20 轮**，算出来超了就在第 0 轮交付物里说明，拆成两批报给任务。

第 0 轮交付：边界清单、造法证实结果、轮次计划（每轮放哪几项）。

## 第 1～N 轮：按计划玩

每轮：

1. 加载整流程 skill 当前版和处置表片，按 skill 的步骤跑一遍；在计划的那一步造本轮的边界。
2. 对外动作（点赞、发送、发布）只在任务允许的测试账号上做；仍然只点一次、失败不重试。
3. 每次页面变化截图，证据 ID 带 `<run_id>-<步号>-<短名>`。
4. 对照预期，给本轮每个边界项下结论：

| 结论 | 什么时候 | 要做什么 |
|---|---|---|
| `handled` | 流程本来就按预期处理了 | 记证据 |
| `fixed_skill` | 流程没处理好，改整流程 skill 就能处理 | 改 skill，**版本 +1**，写清改了哪一步 |
| `fixed_table` | 流程按处置表处理了，但参数不够（比如 5 秒不够） | 写处置表候选行（对象、现象、建议参数、证据），**不直接改正式表** |
| `needs_human` | 处理不了，要人介入 | 在 skill 里写成「停下上报」，记证据 |
| `not_probed` | 造法未就绪 / 未证实，或平台惩罚类没遇到 | 写明原因 |

5. 摸到的写回去（决策 5826ddd7）：

| 发现 | 写到 |
|---|---|
| 只和这条流程有关 | 整流程 skill（版本 +1） |
| 和平台或通用对象有关 | 交付物 `table_candidates`（处置表候选行），转正由本工位另开会话走 PR / 上架 |
| 经验、判断依据 | 交付物 `handbook_seed`（流程手册种子） |
| 不是错，只是能更好 | 交付物 `candidate_improvements`，本轮不改 |

改了 skill 的那一轮，下一轮要把同一个边界**再跑一次**确认改好了。

## 稳定轮与出口

- 清单里每一项都有结论（`not_probed` 也算有结论，但要写明原因）后，用**最终版本**、正常输入连续跑 3 次，3 次都成功才出口。稳定轮里任何一次失败：按上表下结论，改了就版本 +1，稳定轮从 0 重来。
- 出口时从输入类清单里挑 **10 个互不相同的正常输入**，交给第③步验证作输入池。
- 到 20 轮还没出口：停下，交付物写清卡在哪个边界、试过什么。

## 红线

- 只用测试手机、测试账号；生产批次在跑时不排本任务（决策 6ec463c3）。
- 平台惩罚类（风控、验证码、限号）**绝不主动触发**；遇到立即停、释放锁、上报。
- 禁止裸 adb；控制器没有的造法就是「未就绪」，不自己拼命令。
- 运行中不直接改正式处置表和仓库，只交候选行。
