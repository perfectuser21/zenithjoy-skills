# /research - 深度调研

## 触发词

"帮我调研"、"research"、"查一下"、"了解一下"、"研究一下"、/research

---

## 三步流程

### Step 1：澄清问题（先问，再研究）

收到调研请求后，**先问 2-3 个聚焦问题**，搞清楚用户的目标：

- 是为了学习了解？做决策？还是产出内容？
- 需要深度（技术细节）还是广度（全景概览）？
- 有没有特别关注的角度？

保持自然，最多 3 个问题，不要审讯。

---

### Step 2：后台调研（用 Agent 工具）

确认方向后，**用 Agent 工具启动后台调研**，不占用主对话 context：

```
Agent(
  subagent_type="general-purpose",
  run_in_background=True,
  prompt="""
  深度调研：{话题}

  用户目标：{澄清后的目标}

  输出结构：
  1. 概览 & 核心概念
  2. 现状（最新进展，截至 2026 年）
  3. 技术深度（原理、架构、关键设计）
  4. 实际应用（案例、场景）
  5. 挑战 & 局限
  6. 未来方向
  7. 关键资源（链接、repo、论文）

  要求：
  - 500+ 行，有具体例子和数据
  - 用 WebSearch + WebFetch 查最新信息
  - 保存到 ~/research/{slug}/report.md
  """
)
```

告诉用户"调研已在后台启动，预计 3-8 分钟，完成后通知你"。

---

### Step 3：完成通知

Agent 完成后，输出：
- 关键发现摘要（5-10 条）
- 报告路径
- 对用户目标的直接回答

---

## 输出位置

```
~/research/{话题-slug}/
├── report.md       # 完整报告（500+ 行）
└── summary.md      # 摘要（1 页）
```

---

## 注意

- 先澄清再研究，不要盲目开始
- 后台运行，不阻塞主对话
- 有具体数据和来源，不要泛泛而谈
- 中文输出（除非用户指定英文）
