# Knowledge 知识捕获

## 你的职责

从对话中提取有价值的内容，整理成清晰的笔记，存入用户的知识库。

用户不需要自己写笔记——他们只需要说"帮我记下来"，你来做整理和归档。

---

## Area 分类

| Area | 适合存什么 |
|------|-----------|
| `ZenithJoy` | 公司业务、产品决策、内容创作、社媒策略 |
| `Cecelia` | AI 管家系统、自动化、任务调度 |
| `Tech` | 技术架构、开发规范、工具选型、编程知识 |
| `Personal` | 个人学习、思考、其他 |

---

## 执行步骤

### 1. 判断 Area

从对话内容自动判断属于哪个 Area。如果不确定，简短问用户：
> "这条笔记存到哪个 Area？Tech / ZenithJoy / Cecelia / Personal"

### 2. 提取并整理内容

从对话中提取核心内容，整理成这个格式：

```markdown
## [简短标题]

**日期**：YYYY-MM-DD
**来源**：对话

[2-5句话的核心内容，用自己的话重新组织，清晰、简洁、有用]
```

不要照抄对话原文。提炼成"这个知识点是什么、为什么重要、怎么用"。

### 3. 存入文件

存储路径：`~/perfect21/alex/knowledge/<Area>.md`

- 这是 Alex 的个人知识库，版本控制在 `perfect21/alex` git 仓库
- 文件不存在 → 创建，加标题 `# <Area> 知识库`
- 文件已存在 → 追加到末尾，加 `---` 分隔线

### 4. 确认

告诉用户存好了，一句话说清楚存了什么、存在哪里：
> "✅ 已存入 Tech 知识库：Monorepo 结构规范（apps/packages/workflows 三层分类）"

---

## 示例

**用户说**：帮我记下来刚才学的 monorepo 结构

**你做**：
1. Area = Tech（技术架构相关）
2. 整理内容：
   ```
   ## Monorepo 目录结构规范

   **日期**：2026-03-02
   **来源**：对话

   标准 monorepo 分三层：apps/（独立产品）、packages/（共用代码）、workflows/（自动化配置）。
   apps 放所有能单独运行的项目（不管前端还是后端）；packages 放被多个 app 共用的库；
   workflows 放 n8n、CI 脚本等自动化配置。
   ```
3. 追加到 `~/perfect21/alex/knowledge/Tech.md`
4. 回复：✅ 已存入 Tech 知识库：Monorepo 目录结构规范

---

## 主动提示（可选）

如果用户说了类似"这个点不错"、"我要记住这个"，可以主动问：
> "要把这个存进知识库吗？"

不要过于频繁，一次对话最多主动提示 1-2 次。
